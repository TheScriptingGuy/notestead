## Approach
- **Workspace root** (`package.json`): private, `AGPL-3.0-or-later`, `"type": "module"`, `packageManager: yarn@4.16.0`, `engines.node >=22.19.0`, workspaces `packages/*`. `.yarnrc.yml` modelled on upstream's: `nodeLinker: node-modules`, `npmMinimalAgeGate: 1w`, `nmHoistingLimits: workspaces`, `enableGlobalCache: false`, plus `enableTelemetry: false`.
- **Pin** `upstream/joplin-version.json`: exactly the ADR-0005 §1 values. The full web SHA was confirmed in the reference clone: `git rev-parse v3.7.21^{commit}` = `e41516e669efb693b009bedb21f3eb1fcbea4fc9`.
- **Workspaces created in this story** (see Deviations):
  - `packages/web-build`: hosts the pin checks (it is the package that works with the pinned upstream tree; M1-S2 reuses `pin.ts` and the cached upstream fetch).
  - `packages/headless`: depends on `"joplin": "3.7.1"` exactly, so `yarn.lock` pins the CLI and its `@joplin/*` tree (M1-AC3, test plan interpretation 2). Its unit-tested module `findInstalledCli` resolves the installed CLI's version and bin, which the M1-S5 supervisor needs to spawn it.
- **TypeScript**: ESM sources run directly by Node's built-in type stripping (no build step for the scripts). `tsconfig.base.json` uses `module: nodenext`, `strict`, `noEmit`, `allowImportingTsExtensions`, `erasableSyntaxOnly`, `verbatimModuleSyntax`. One root `tsconfig.json` type-checks `packages/*/{src,bin}/**`, `tests/**/*.ts` and `*.config.ts`; per-package `tsconfig.json` files cover `src/**` and `bin/**`.
- **Jest** (`jest.config.js`): ts-jest 29.4.6 transpiles to CommonJS without type-checking (lint runs tsc). `testMatch` covers `packages/*/src/**/*.test.ts`, `tests/unit/**`, `tests/integration/**`; `tests/acceptance/` and `tests/fixtures/` are ignored, and `*.mts` is never matched.
- **ESLint** (`eslint.config.js`): flat config written for this repo, modelled on upstream's rule choices (same parser and plugins: `@typescript-eslint`, `@stylistic`, `jest`; same style). It adds `jest/no-focused-tests` and `jest/no-disabled-tests` for `**/*.test.ts`, `playwright/no-skipped-test` and `playwright/no-focused-test` for `tests/e2e/**/*.spec.ts`, and a `no-restricted-syntax` ban on `waitForTimeout` for `tests/**` and Jest files. Type-aware linting uses `projectService` (nearest tsconfig per file). `no-floating-promises` allows the `node:test` `describe`/`it` calls (typescript-eslint's documented `allowForKnownSafeCalls` pattern).
- **`corepack yarn lint`** = `eslint --max-warnings 0 . && tsc -p tsconfig.json && tsc -p tests/acceptance/tsconfig.json`. There's no cache file, so the git tree stays clean.
- **Playwright** (`playwright.config.ts`): 1.59.1 (upstream's version), `testDir: tests/e2e`, `forbidOnly`, one worker locally, `retries: 1` only in CI, trace on failure, Chromium project. Minimal on purpose: the harness is M1-S6.
- **`check:pin`** (`packages/web-build/src/{pin,lockfile,checkPin}.ts`, entry `bin/check-pin.ts`):
  - Validates every field of the pin. Each problem starts with its dotted path (for example `web.commit: must be a full commit SHA …`).
  - A missing or non-object section is reported once, without cascading into its fields. Non-JSON or unreadable files are named by path.
  - It then parses `yarn.lock` (Berry format; a small parser for top-level entries and their `version:`/`resolution:` fields; works for lockfile versions 8 and 10) and checks that `cli.npm` resolves to exactly `cli.version` and that every lockstep `@joplin/*` resolves to `<minor>.x`. `@joplin/fork-*` and `@joplin/turndown*` are exempt, and unknown `@joplin/*` packages are checked (fail closed).
  - Exit codes: 0 OK, 1 invalid, 2 usage.
- **`check:no-upstream-copy`** (`packages/web-build/src/{upstreamCopy,checkNoUpstreamCopy}.ts`, entry `bin/check-no-upstream-copy.ts`):
  - Takes the blob IDs of the upstream tree at `web.commit` from `git ls-tree -r`.
  - Hashes the git-**tracked** regular files of at least 1 KiB under `--root` as git blob IDs (SHA-1 of `blob <len>\0<bytes>`). It skips symlinks, deleted files, untracked and ignored files.
  - On failure it names each copy with its upstream path(s).
  - Without `--upstream`, it fetches the pinned commit itself with `git fetch --depth 1 --filter=blob:none` into `${NOTESTEAD_CACHE_DIR:-${XDG_CACHE_HOME:-~/.cache}/notestead}/upstream/<commit>.git`. The fetch goes to a temp directory and is renamed into place, and the cache is reused per commit. No upstream blobs are downloaded (456 KB on disk). CI and the Pi use the same code path.
  - The pin is always read from this repo unless `--pin` is given.
  - All binary and text files ≥ 1 KiB are scanned. That is stricter than ADR-0009's "text file" wording, and it also catches copied upstream icons.

## ADR deviations and interpretations
1. **Only two workspaces now** (`web-build`, `headless`) instead of all five in ADR-0009's layout.
   - `web`, `data-api-client` and `mcp` have no code in this story. Creating them would need placeholder code with placeholder tests, and M1-AC1 requires *real* unit tests.
   - Each will be created by the first story that needs it (M1-S4 / M1-S5 / M4).
   - The layout itself is unchanged.
2. **The check scripts live in `packages/web-build`.** ADR-0009 says the scripts live in `packages/**` without naming a package. `web-build` is the package that handles the pinned upstream tree (M1-S2 clones it too). No new package was invented.
3. **ESLint plugin subset.** Upstream also uses `eslint-plugin-react`, `@seiyab/eslint-plugin-react-hooks`, `eslint-plugin-import` (`import/prefer-default-export`), `eslint-plugin-promise`, `eslint-plugin-github` and its own `joplin/*` rules.
   - We have no React code (ADR-0009: react-hooks "where relevant").
   - `import/prefer-default-export` conflicts with our named-export modules, and it would make QA's type-error-only fixture fail eslint before `tsc` runs (T07).
   - The rest add dependency weight for no current benefit (see Follow-ups).
4. **Function-type arrow spacing** is `() => void` rather than upstream's `()=> void`, to match QA's committed acceptance suite (`tests/**` is not mine to edit). Implemented with the non-deprecated `overrides.arrow: 'ignore'` plus `@stylistic/arrow-spacing`.
5. **M1-AC3 wording.** As instructed, I implemented what QA's tests specify: the minor rule applies to all `@joplin/*` except `@joplin/fork-*` and `@joplin/turndown*`. The architect is amending the AC text.
6. **`check:no-upstream-copy` scans all tracked files ≥ 1 KiB**, binary included. ADR-0009 says "text file"; scanning binaries too is stricter and also catches copied upstream icons. The license-header half of the ADR-0009 check is not in M1-AC4 and not implemented (test plan interpretation 5).
7. **Config files at the repo root** (`jest.config.js`, `playwright.config.ts`, `eslint.config.js`, tsconfigs) were written by me because the test plan places these requirements on the implementation. QA may take ownership of the Jest/Playwright harness config in M1-S6.
