## Approach
### `check:workflows` (M1-AC8)
- **Where it lives.** `.github/scripts/` (ci-cd-owned), as the orchestrator decided. The root `package.json` script is `node .github/scripts/check-workflows.ts` (Node type stripping, no build step).
  - **Deviation from the test plan's wording.** The contract says the logic lives in `packages/**` (ADR-0009 A2). The orchestrator routed it to the ci-cd specialist and preferred `.github/scripts/`. The ADR-0009 principle still holds: the script runs identically on the Pi and in CI, and the workflows only call it. If the lead prefers `packages/web-build` (or a private `tooling` workspace), the three `.ts` files move unchanged.
  - **Files:**
    - `check-workflows.ts`: the CLI
    - `workflowRules.ts`: the repo rules
    - `pinnedTools.ts`: tool download, verify and version check
    - `pinned-tools.json`: the pinned versions and checksums
    - `tsconfig.json`
- **Shared files touched** (all in root config, for the lead to judge):
  - `package.json`:
    - the `check:workflows` script
    - `&& tsc -p .github/scripts/tsconfig.json` appended to `lint`, so the new TypeScript is type-checked. `eslint .` already lints `.github/**`, because flat config doesn't ignore dot-directories.
    - devDependency `yaml` `2.9.1` (ISC, no dependencies, ships its own types; older than the 1-week `npmMinimalAgeGate`)
  - `yarn.lock`: the one `yaml@npm:2.9.1` entry.
- **actionlint (binding contract).**
  - **Pin.** 1.7.12 is pinned in `.github/scripts/pinned-tools.json` with the sha256 of the linux amd64 and arm64 tarballs. I downloaded all four tarballs and checked that their sha256 matches both GitHub's asset digest and actionlint's own `actionlint_1.7.12_checksums.txt`.
  - **Resolution:**
    1. `ACTIONLINT` if set; a missing path fails and names the path.
    2. Otherwise `${XDG_CACHE_HOME:-~/.cache}/notestead/tools/actionlint-1.7.12/actionlint`. On first use it is downloaded with `fetch`, the tarball's sha256 is checked before extraction, the binary is extracted with `tar -xzf` into a temp dir in the cache dir and renamed into place. Nothing is written into the repo.
  - **Version check.** The binary's `-version` first line must equal the pin; otherwise the check fails and names the version found (this applies to the override too). Before linting it prints `actionlint 1.7.12 (<path>)`.
- **shellcheck: pinned, not disabled.** 0.11.0 is pinned the same way (`SHELLCHECK` override, `--version` check) and passed as `-shellcheck=<abs path>`.
  - `pyflakes` is disabled with `-pyflakes=`, since there are no `shell: python` steps.
  - `SHELLCHECK_OPTS` is removed from actionlint's environment, so the machine can't change the result.
  - The pinned shellcheck caught a real SC2012 in my first `web-bundle.yml` draft, which shows it is worth keeping.
- **actionlint invocation.**
  - Command: `actionlint -no-color -shellcheck=<pinned> -pyflakes= <files…>`, with explicit file arguments (works outside git). No `-ignore`, and there is no `.github/actionlint.yaml`.
  - It runs from the workflows' project root: the repo, or the directory holding `.github/` for a tree elsewhere. That keeps its paths readable (`.github/workflows/x.yml`) instead of `../../../tmp/...`.
  - Its output passes through, and its non-zero exit fails the check.
- **Repo rules** (`workflowRules.ts`, parsed with `yaml`, so quotes, comments and flow style are handled). Findings use actionlint's format, `<file>:<line>:<col>: <message> [<rule>]`, and every finding in every file is reported.
  - `[sha-pin]`: step and job-level `uses:` in workflows; `runs.steps[].uses` and a `docker://` `runs.image` in `<dir>/../actions/**/action.y{a,}ml`. Allowed values are `./…`, `docker://…@sha256:<64 hex>`, and `owner/repo[/path]@<40 lowercase hex>`.
  - `[permissions]`: each job must have its own `permissions:` mapping (`{}` is fine). `write-all`/`read-all` fail at job or workflow level, and any other scalar fails as "not a mapping". Scope names and values are left to actionlint's own `[permissions]` rule.
  - `[pull-request-target]`: in a `pull_request_target` workflow, an `actions/checkout` whose `with.ref` or `with.repository` contains `github.event.pull_request.head`, `github.head_ref` or `refs/pull/` fails. I implemented this targeted rule rather than banning the trigger, so a future label or title workflow stays possible. `actions/checkout` v7 also refuses fork PR checkouts under `pull_request_target` by default.
  - A YAML parse error is reported as `[yaml-syntax]` (actionlint reports it too).
- **Directory handling.** A missing directory, or one with no `*.yml`/`*.yaml`, fails and names the directory. Relative `--dir` paths resolve against `INIT_CWD`, where the user typed the command. Exit codes: 0 no findings, 1 findings or a failure, 2 usage error.
- **No unit tests of its own.** Jest only collects `packages/*/src` and `tests/**`, which I don't own. QA's 24 black-box acceptance tests cover every rule, its negative controls and the tool pinning.

### Workflows (M1-AC9, M1-AC27 requirements 1–6 of the verification procedure)
- **Pinned actions.** Each SHA was resolved read-only through the GitHub API from the latest release tag on 2026-10-04 (all are lightweight tags pointing at commits). The inputs used were checked against each version's `action.yml`.

  | Action | Tag | Commit |
  |---|---|---|
  | `actions/checkout` | v7.0.1 | `3d3c42e5aac5ba805825da76410c181273ba90b1` |
  | `actions/setup-node` | v7.0.0 | `820762786026740c76f36085b0efc47a31fe5020` |
  | `actions/cache` (and `/save`) | v6.1.0 | `55cc8345863c7cc4c66a329aec7e433d2d1c52a9` |
  | `actions/upload-artifact` | v7.0.1 | `043fb46d1a93c77aae656e7c1c64a875d1fc6a0a` |
  | `actions/download-artifact` | v8.0.1 | `3e5f45b2cfb9172054b4087a40e8e0b5a5461e7c` |
- **`.github/actions/setup`** (composite):
  - `setup-node` with Node **22**, as `docs/testing/strategy.md` ("22 LTS in CI") and ADR-0009 (Node 22 in containers) specify. Node 22 ships corepack, and `package-manager-cache: false` is set.
  - `actions/cache` on `.yarn/cache` and `~/.cache/node/corepack`, key `yarn-<os>-<arch>-<hash(yarn.lock, .yarnrc.yml)>`.
  - Then `corepack yarn install --immutable`.
  - The Pi runs Node 24, so both majors are exercised.
- **`ci.yml`:**
  - **Triggers:** push to any branch, `pull_request`, `workflow_dispatch`. Pull requests from this repo's own branches skip the job, because their push run already tests them; `pull_request` runs are for forks. Concurrency cancels superseded PR runs.
  - **Matrix:** `ubuntu-24.04` and `ubuntu-24.04-arm`, `fail-fast: false`, `permissions: contents: read`, checkout with `persist-credentials: false`.
  - **Steps:** lint, test, `check:workflows`, `check:pin`, `check:no-upstream-copy`, then the acceptance suites. Each runs `if: !cancelled() && setup succeeded`, so one run reports every result.
  - **Acceptance step.** It runs `node --test --test-concurrency=1 --test-reporter=spec --test-reporter-destination=stdout --test-reporter=junit --test-reporter-destination=test-results/junit/acceptance-${RUNNER_ARCH}.xml 'tests/acceptance/**/*.test.mts'` directly, not through `corepack yarn test:acceptance`. I checked locally with a probe suite that node:test ignores reporter options placed after the file glob: the JUnit file was never written. The node:test reporter also doesn't create the JUnit directory, so the step runs `mkdir -p` first.
  - **arm64 NEG step:**
    - command: `unset NOTESTEAD_ALLOW_ARM64_WEB_BUILD; timeout --kill-after=10 120 corepack yarn test:optin:build`
    - passes only on a non-zero, non-timeout exit whose output contains `Refusing to start the ~43-minute native arm64 web build`
    - the log is saved to `test-results/neg/t90-interlock-arm64.log`
  - **Always (`if: always()`):** a job summary from `.github/scripts/junit-summary.ts` (tests/pass/fail/cancelled/skipped/todo/duration plus failed test names), and the upload of `test-results/` as `test-results-ci-<runner>`. Hidden paths, i.e. the upstream git cache under `test-results/.cache`, are excluded by upload-artifact's default.
- **`web-bundle.yml`:**
  - **Triggers:** push and `pull_request` filtered to the bundle's inputs (pin, `packages/web-build/**`, the M1-S2 tests and their support files, this workflow, the setup action, the summary script, `package.json`, `yarn.lock`), plus `workflow_dispatch`. The same fork-only rule for `pull_request` applies.
  - **`build` job** (`ubuntu-24.04`, `contents: read`, 150 min):
    1. Frees disk space when less than 25 GiB is free, by removing the preinstalled Android, .NET, GHC and CodeQL toolchains. The upstream work dir needs about 13 GB. `df` is printed before and after.
    2. Runs **T90 itself**: `NOTESTEAD_BUILD_OUT=$RUNNER_TEMP/web-bundle-out NOTESTEAD_BUILD_WORK=$RUNNER_TEMP/web-build-work node --test … --test-reporter=junit --test-reporter-destination=test-results/junit/m1-s2-t90.xml tests/acceptance/m1-s2/optin/ac5-build.optin.mts`.
    3. Prints `SHA256SUMS`, also into the job summary.
    4. Uploads **that directory** as `web-bundle-<web.tag>`, with `compression-level: 0` because the tarball is already zstd. There is no second build.
  - **Cache by pin hash (ADR-0001).** After a green T90, `actions/cache/save` stores the artifact directory under the key `web-bundle-<hash(upstream/joplin-version.json)>-<hash(packages/web-build/** minus node_modules)>`, for later consumers (images, `e2e.yml`).
    - It never skips T90, so every run that is used as evidence is a full build.
    - I didn't cache upstream's own yarn cache. It sits inside the `--work` dir, and restoring it there would depend on `build`'s work-dir marker contract. The gain is a few minutes at most.
  - **`verify-artifact`** (`needs: build`, both runners, `permissions: {}`): downloads the artifact, prints `SHA256SUMS`, checks that the artifact holds exactly `SHA256SUMS`, `bundle-manifest.json` and `web-bundle-<tag>.tar.zst`, then runs `sha256sum --strict -c SHA256SUMS`.
- **Least privilege.** Every workflow declares `permissions: {}`. Every job declares its own permissions (`contents: read` or `{}`), and no job has a write scope. No secrets are used, and there is no `pull_request_target`.

## Commands run (Pi, arm64)
```sh
corepack yarn add -D -E yaml@2.9.1
curl -sSfLO <the four tool tarballs + actionlint_1.7.12_checksums.txt>; sha256sum *.tar.gz   # in ~/joplin-web-app-work/tools/verify
corepack yarn check:workflows                       # exit 0 (after fixing SC2012 found by the pinned shellcheck)
node --test --test-concurrency=1 --test-reporter=spec 'tests/acceptance/m1-s3/*.test.mts'
corepack yarn lint
corepack yarn test
node --test --test-concurrency=1 --test-reporter=spec --test-reporter-destination=stdout \
  --test-reporter=junit --test-reporter-destination=test-results/junit/acceptance-ARM64.xml 'tests/acceptance/**/*.test.mts'
```
