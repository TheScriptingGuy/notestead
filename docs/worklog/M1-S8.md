### Approach: FU-S6a-1 (commit `2e68c17`, `chore(lint): …`)
Built-in rules only, in the existing "No fixed sleeps in tests (ADR-0007)" block (same files: `testFiles` minus `sleepExempt`):
- **`require()`/`import()` of a timers module** (`timers`, `node:timers`, `timers/promises`, `node:timers/promises`; string literal or substitution-free template literal), `no-restricted-syntax`. The call is reported **whatever is done with the result**, not only member access. That is the plan's "or banned outright in tests" option. Reasons:
  - It mirrors the M1-S6a ban on the namespace and default static imports: the run-time module object is the same thing.
  - It closes the alias form (`const t = require('timers'); t.setTimeout(…)`), which a member-access-only selector misses.
  - No test loads these modules at run time (`git grep` before the change found no use), and a test that needs an allowed name (`setImmediate`) can import it statically, where `no-restricted-imports` checks the name.
  - The report sits on the module argument, which is on the `// NEG` line.
- **`scheduler`** added to the `no-restricted-imports` `importNames` of the timers modules (`timersImportNames`), so `import { scheduler as s }` is reported on the import line.
- **`Atomics.wait`**, `no-restricted-syntax`, reported wherever it is taken:
  - dotted on `Atomics` or on a global's `Atomics` (`globalThis.Atomics.wait`);
  - computed with the string key `'wait'`;
  - destructured from `Atomics` (`const { wait } = Atomics`).

  `Atomics.store/notify/load` are not matched. `Atomics.waitAsync` stays under the review's accepted risk A1, as the plan says.
- Two new messages name the form (the timers modules; `Atomics.wait`). The header comment and the rule comment were updated.
- **esquery note:** esquery regexes cannot contain `/`, so the module regex is `/^(node:)?timers(.promises)?$/`, with `.` standing for the slash.

### Approach: shellcheck (commit `79546b0`, `fix(web): …`)
- **SC2101** (line 15, `*[[:space:]{}\"\'\`\\#]*`): this is a shellcheck false positive. shellcheck takes a named class inside a longer bracket expression for a mistake. The set of refused characters is unchanged; it is now split into two bracket expressions in one case pattern, `*[[:space:]]* | *[{}\"\'\`\\#]*`, with the same escapes. No directive was needed.
- **SC2018/SC2019** (line 41, `tr 'A-Z' 'a-z'`): now `LC_ALL=C tr '[:upper:]' '[:lower:]'`. WHATWG `URL.host` lower-cases ASCII only, so the C locale is the faithful choice. A bare `[:upper:]` would follow the container's locale; for example, a Turkish locale maps `I` to dotless `ı`, which the host check would then refuse. No directive was needed.
- **Behaviour check (differential):** the old and new scripts, each with `exec caddy …` replaced by a `printf` of every exported variable, were run on the same inputs:
  - shells: busybox `sh` (the shell of the Alpine-based `caddy` image) and dash;
  - locales: `LC_ALL=C`, `LANG=C.UTF-8`, `LC_ALL=tr_TR.UTF-8`;
  - environments: 816 in total. Every ASCII character 1–127 plus `é`, `É`, `İ` was put into each variable. There were also trailing-slash, default-port, mixed-case, credential, query, fragment, path and IPv6 URLs, and the valid and invalid COEP and proxy cases.

### Approach: M1-AC30 to M1-AC32, `check:workflows` (commit `6b4be8a`)
- **M1-AC30, aliases: rejected and resolved.** Every alias (`*name`) and every merge key (`<<`, which GitHub's parser may honour and `yaml` 1.2 does not) is a `[yaml-alias]` finding at its position. The other rules then run on the **resolved** nodes (`Alias.resolve(doc)` wherever a node is read), so an alias cannot hide a step or a job even if the alias rule were ever relaxed. NEG 2 therefore reports `[yaml-alias]`, `[permissions] aliased-job` and `[sha-pin] … aliased-job` together.
- **`[workflow-shape]`:** `jobs:` that is not a mapping, a job that is not a mapping, `steps:` that is not a sequence (or is empty), and a step that is not a mapping, in workflows and composite actions. Each names the job id (and the step number). They are reported even when actionlint also reports a `[syntax-check]`.
- **M1-AC31, `[forbidden-trigger]`:** `pull_request_target` and `workflow_run` in the scalar, sequence and mapping forms of `on:`, at the trigger's position, naming it. `[pull-request-target]` is gone. No allow-list (none is approved; an entry would need an ADR-0009 A7 amendment).
- **M1-AC32, `[local-action]`:** the rule module returns every step `uses: ./<path>` (workflows and composite actions); `check-workflows.ts` resolves each against the project root (the repo, or the tree holding `.github/` for `--dir`), as GitHub resolves it against the workspace, to `action.yml`, else `action.yaml`.
  - Missing: `[local-action]` on the workflow line, naming the `./<path>` and the expected file.
  - Outside the project (`./../x`, or an action file that is a symlink leading out): `[local-action]`.
  - Found: checked once with the action rules (its findings name the action file), and the actions it uses are followed in turn. If it has findings, the workflow line also gets a `[local-action]` line naming the workflow, the `./<path>` and the count.
  - The action files under `.github/actions/` are still all checked, used or not.
