## Approach
### M1-AC28: `web-build import <artifact-dir> --out <dist> [--pin] [--upstream]`
Code in `packages/web-build/src/importBundle.ts` and `src/tar.ts`, wired in `src/webBuild.ts` and the workspace script `import`.
- **`--out`** must be absent or an empty directory. Anything else fails, naming it, before anything is read or written.
- **Before extracting** (contract order):
  1. The three artifact files exist (a tarball of another tag is named in the error).
  2. `SHA256SUMS` (sha256sum format; malformed lines and conflicting duplicates fail) has a matching line for the tarball **and** for `bundle-manifest.json`. A missing line fails closed.
  3. `bundle-manifest.json` `upstream.repo`, `.tag` and `.commit` equal the pin's `web.*`; every mismatching field is named with both values. `files` is validated too: shape, 64-hex sha256, non-negative size, a safe normalized relative path, no duplicates, no path that is both a file and another file's directory.
  4. The tarball is decompressed in memory with Node's zstd, **bounded** by the listed sizes plus 8 KiB per file plus 1 MiB, so a decompression bomb stops early.
  5. `tar.ts` reads the members itself: ustar headers with checksum, pax `x` headers (`path`, `linkpath`, `size`), GNU `L`/`K` long names; pax `g` headers only when they set no path or size. Extended headers are metadata. Every member must be a regular file or a directory with a relative path without `..`, empty or `.` segments or backslashes (a leading `./` is fine); every regular file must be listed; duplicates fail. All offending members are listed in one error.
- **Extraction** writes the parsed member bytes (`wx`, never through the `tar` binary, so no link or path semantics apply) into a staging dir `.<out>.import-<pid>` next to `--out` (the test plan's suggested approach), with modes 0644/0755 whatever the umask, so the non-root server can read them.
- **After extracting:** `hashFiles` of the staging dir must equal `files` exactly (missing, extra, sha256 and size each named), then the `verify` command's own code path (`runVerify`, with `--upstream`) runs on it. Only then is the staging dir renamed to `--out`. A `finally` removes the staging dir, so on any failure `--out` is absent or empty and nothing stays beside it.

### `deploy/web/`: Containerfile, Caddyfile, entrypoint
- **Base:** `docker.io/library/caddy:2.11.6-alpine` pinned by its OCI index digest `sha256:d44355d3…10d9` (read from the registry's `Docker-Content-Digest`; the index lists linux/amd64, arm64/v8 and others). No `VOLUME` in the base, so no anonymous volumes are left behind by `podman rm`.
- **Hardening:** the base's `/usr/bin/caddy` carries the file capability `cap_net_bind_service=ep`; under `--cap-drop=ALL` + `no-new-privileges` executing it fails, so the image runs `setcap -r` (the only `RUN`). `USER 65532:65532`; Caddy's XDG dirs and `HOME` point into `/tmp` (tmpfs); `admin off`, `persist_config off`, `auto_https off`, so Caddy writes nothing. Ports 8080/8089 are unprivileged.
- **Bundle:** `COPY --from=dist --chown=0:0 . /srv/www/` from the named build context, per the image contract.
- **Entrypoint** (`notestead-web-entrypoint.sh`, POSIX sh): requires `JOPLIN_SERVER_URL` (scheme://host[:port], no credentials/path/query) and `JOPLIN_SERVER_PUBLIC_URL` (http(s), no credentials/query/fragment; trailing `/` removed). It derives `JOPLIN_SERVER_HOST`'s default as WHATWG `URL.host` (lower case, default port dropped), because upstream's `isValidOrigin` compares `new URL(APP_BASE_URL).host` (`upstream:packages/server/src/utils/routeUtils.ts` at `server-v3.7.2`). It validates `COEP` (`credentialless`/`require-corp`), `TRUSTED_PROXIES` (addresses/CIDRs), `CLIENT_IP_HEADER` (one header name, only together with `TRUSTED_PROXIES`), and refuses whitespace, braces, quotes, backslashes and `#` in values, because Caddy substitutes `{$VAR}` before parsing. Then it `exec`s `caddy run --config /etc/caddy/Caddyfile` (the file the R3-neg variant replaces). Exit 64 with a named reason on bad config.
- **Caddyfile** (rules of ADR-0002):
  - Rule 1/2: `handle_path /joplin-server/*`, `handle /api/*` → `reverse_proxy {$JOPLIN_SERVER_URL}` with `header_up Host {$JOPLIN_SERVER_HOST}`; everything else under `/joplin-server/` is `respond 404`.
  - Rule 3: `header_up -Origin -Referer -Cookie -Cf-Access-Jwt-Assertion -Cf-Access-Authenticated-User-Email`, `header_down -Set-Cookie`.
  - Rule 4: `header_up X-Real-IP {client_ip}` (one line, in the shared proxy snippet, so the R3-neg variant removes it for both listeners); global `trusted_proxies static {$TRUSTED_PROXIES}`, `trusted_proxies_strict`, `client_ip_headers {$CLIENT_IP_HEADER}`. Empty variables expand to no ranges and no headers (checked with `caddy adapt`): nothing is trusted by default.
  - Rule 5: `flush_interval -1`; no request buffering.
  - Rule 6: `@share path_regexp ^/shares/([A-Za-z0-9]+)$` → `redir {$JOPLIN_SERVER_PUBLIC_URL}/shares/{re.share.1} 302`; `/shares/` and `/shares/<id>/x` fall to the 404.
  - Rule 7: access logs of both listeners to stdout through a `filter` encoder (`token` query parameter, `X-Api-Auth`, `Authorization`, `Cookie`, `Cf-Access-Jwt-Assertion`, `Cf-Access-Client-Secret` → `REDACTED`). The **default logger** gets the same filter, because Caddy's error entries (for example a 502 when the server is down) also carry the request with its headers.
  - Rule 8: the route sets `Cache-Control: no-store, no-transform` (not deferred, so it is also on Caddy's own 404/302/502), and the proxy drops the upstream's `Cache-Control` (`header_down -Cache-Control`) so the two are never merged.
  - Static (`handle`, root `/srv/www`): COOP `same-origin`, COEP `{$COEP}`, `nosniff`, `no-referrer` (site-wide), `Cache-Control: no-cache, no-transform` **deferred** (QA's pitfall: `encode` skips responses that already say `no-transform`), `application/wasm` for `*.wasm`, `encode zstd gzip`, `file_server` (ETag from mtime and size; Caddy suffixes it with the encoding and answers `If-None-Match` with 304 either way).
  - `:8089`: the same `/joplin-server/api/*` proxy and nothing else (404).
- **Healthcheck:** no `HEALTHCHECK` in the Containerfile: podman's default OCI format drops it with a warning, and compose healthchecks are M1-S5/M1-S6 scope. The image has busybox `wget`, and `deploy/web/README.md` gives the command.

## Upstream-first notes
- No shims and no `patches/`. Upstream is consumed as the packaged bundle (`package`/`import`) and the unmodified `joplin/server` behind the proxy.
- The proxy exists only because the server's CORS allow-list is hard-coded (ADR-0002); the upstream-first proposal `CORS_ALLOWED_ORIGINS` is the architect's (ADR-0002 Alternatives). Nothing new here.

## ADR deviations
1. **Location of the image files.** ADR-0009's layout lists `packages/web/` ("Containerfile + Caddyfile template for the `web` image"). The test plan's image contract (binding, `docs/test-plans/M1-S4.md`) and the orchestrator's brief use `deploy/web/Containerfile` with build context `deploy/web`, so the files are in `deploy/web/`. It is a layout difference only (the image is config, not a workspace package). **For the architect:** amend ADR-0009's layout, or tell me to move it and QA to change the contract.

Interpretations within the contracts:
- **Proxied responses are not compressed.** ADR-0006 says Caddy compresses because `no-transform` stops Cloudflare's compression; M1-AC12 asks for it on bundles. I compress static files only: the S2-verified streaming proxy (C5, 100 MiB under 128 MiB) stays untouched. Follow-up below.
- **`-Server`** (as in spike S2) is applied site-wide; Caddy's own 502 still says `Server: Caddy`. Not a requirement.

## Follow-ups
- **Compression of proxied responses** (sync JSON and E2EE payloads) behind Cloudflare, where `no-transform` turns off Cloudflare's compression (ADR-0006). Measure it with the C5 memory limit before turning it on; architect's call.
- **Precompressed sidecars** (`file_server precompressed zstd gzip`): the real `app.bundle.js` (~18 MB) is compressed on every full download today. Sidecars written by `import` or at image build would save CPU on the Pi. Not needed for the ACs.
- **ETags** come from mtime and size, and `import` writes files at import time, so every image build changes every ETag (a full download after each upgrade, never a stale file). Setting mtimes from the tar would keep them stable across rebuilds of the same artifact.
- **Healthcheck:** compose (M1-S5/M1-S6) can use `wget -q -O /dev/null http://127.0.0.1:8080/`.
- **x64:** the contract suite runs in CI from M1-S8 (PENDING-CI until then). The base image is multi-arch and the only `RUN` (`setcap -r`) runs natively per architecture.
- **ADR-0009 layout** (`packages/web/` vs `deploy/web/`): see ADR deviations.
