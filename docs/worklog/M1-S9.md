## Approach
All code is in `packages/web-build` (ADR-0009 A2/A7), run by Node type stripping through root or workspace scripts.

- **M1-AC26, `check:pin`** (`src/checkPin.ts`, `src/lockfile.ts`):
  - `--headless-manifest <file>` (default `packages/headless/package.json`): `dependencies.<cli.npm>` must equal `cli.version` as a string. The failure line names the manifest path and `dependencies.joplin`.
  - Lockfile source rule: for the `cli.npm` entry and every `@joplin/*` entry (lockstep and forks alike), `resolution:` must be exactly `<name>@npm:<version>`. Otherwise the line names the entry and its protocol (`resolutionProtocol()`: `https`, `git+ssh`, `github`, `file`, `link`, `portal`, `exec`, `patch`, or an npm resolution that doesn't match its version). The name comes from `resolution:`, never from the key. Other packages are not checked (T319).
  - Lockfile and manifest problems are reported together before exiting 1.
- **M1-AC25, `check:no-upstream-copy`** (`src/licenceHeader.ts`):
  - It reads `upstream:LICENSE` at `web.commit` through the same tree as the hash check (`--upstream`, or the cached blobless fetch, which lazily fetches the one blob). The header is its first non-empty line; the holder comes from its first `Copyright (c) <years> <holder>` line. Nothing is hard-coded, so no upstream text is committed here.
  - Every tracked regular file of any size is read. Each line is stripped of a comment prefix (`//`, `#`, `*`, `/*`, `/*!`, `<!--`, `;`, `--`, `>`), a comment suffix and surrounding whitespace. A file fails when one line equals the header **and** another matches `Copyright (c) <years> <holder>`, with any year, range or list of years, an optional final period, and `(c)` in any case. A header quoted inside a sentence (as in ADR-0009 A10) is not a whole-line match.
- **M1-AC24, `check:licenses`** (`src/checkLicenses.ts`, `src/spdx.ts`, `src/installedPackages.ts`, `src/licenseExceptions.ts`, `bin/check-licenses.ts`):
  - **Walker.** It covers `<root>/node_modules` and the `node_modules` of each workspace in `<root>/package.json` (`dir/*` and plain paths; other globs are refused rather than half-understood). It recurses through nested `node_modules`, skips symlinks and dot entries, and counts as a package only a directory directly under `node_modules/` or `node_modules/@scope/` with a `package.json`. An unreadable `package.json` is listed under its directory name and denied.
  - **SPDX.** A small recursive-descent parser: `AND` binds tighter than `OR`, parentheses, `WITH`, `+`, `LicenseRef-`/`DocumentRef-`. Operators are upper case only, as in the SPDX spec; the real tree has no lower-case operators. IDs compare case-insensitively.
  - **Allow-list.** ADR-0009 with A8. A leaf passes when its ID, minus `-only`/`-or-later` (or a `+`), is on the list. Any `WITH` exception is denied (A8: exceptions are per package).
  - **Legacy forms (A9).** The `licenses` array becomes the OR of its types, with compound types parenthesized. A `license` object becomes its type. An entry without a type makes the whole form missing. The listing marks these `[legacy …]`, and the report's `license` is the derived expression.
  - **Output.**
    - One stdout line per package: `<name>@<version>  <licence>  <status>  (<path>)`.
    - On failure, one stderr line per problem. A denied package gets `DENIED <name>@<version> (<path>): <reason>`.
    - `--report` writes `{packages:[{name,version,path,license,status}]}`.
  - **Exception list.**
    - Schema as in the test plan. Unknown keys and duplicate `name@version` entries are also flagged (fail closed), and `"//"` keys are allowed.
    - An invalid entry is reported and not applied.
    - An entry whose package is installed only at other versions fails (contract).
    - An entry for a package that isn't installed is noted as unused, since it may serve the upstream notices.
    - An entry for an allow-listed package is noted as unneeded.
- **The real exception list** (`packages/web-build/license-exceptions.json`): one entry each for the three packages `check:licenses` denies in this repo (it denied exactly these with an empty list):
  - `@joplin/onenote-converter@3.7.1`: `MPL-2.0-no-copyleft-exception`. Evidence: the tarball's `package.json` and its MPL-2.0 `LICENSE` (sha1 recorded), plus the source at the tarball's `gitHead`. The reason is the architect's compatibility position.
  - `node-bitmap@0.0.1`: **MIT**, established. The tarball's `README.md` § License states "(The MIT License) Copyright (c) 2012 Yusuke Hata" with the full MIT text; the GitHub repo README says the same and has no tags. `noticeText` is that section verbatim.
  - `tkwidgets@0.5.27`: **MIT**, established. The tarball has no licence field or file. The source repo `laurent22/tkwidgets` has an MIT `LICENSE` (added in `d8f23c3`, 2018-02-16), unchanged at commit `ac0be42b…` whose message is "0.5.27" (the repo has no tags; verified by fetching the raw file at that SHA and diffing). `noticeText` is that file verbatim.
  - Licences were established for both packages without a licence field, so no entry is `UNKNOWN` and none is a pre-publish blocker (`prepublishBlocker: false` on all three).
- **M1-AC29, notices** (`src/notices.ts`, `src/spdxTexts.ts`; command wiring in `src/webBuild.ts`):
  - **Closure.** It parses upstream's `yarn.lock` (`parseLockfile` now also returns descriptors and `dependencies`) and applies the root `resolutions` (`name`, `name@range`, `parent/name`, scoped). Lookup is exact by descriptor, or by descriptor plus a `::locator=…` suffix (patch/link from resolutions). It skips `link:`/`portal:` and lists aliases under the resolved name. Workspaces contribute their `package.json` `dependencies`. On the S1 tree: 1500 closure packages, 11 not installed (`fsevents`, `lightningcss-*` for other platforms), so they are reported as a note and skipped.
  - **Banners.** For each `/* … */` comment of each `*.LICENSE.txt` under the dist, three rules name packages; all three can apply to the same comment:
    - its first content line, when that is an installed package name (the object-assign form);
    - any line that is only a file name (`react-dom-client.production.js`), naming the installed packages that ship that file at `<pkg>/`, `cjs/`, `umd/`, `dist/` or `lib/` (prose such as "node.js" in a sentence is not a file name);
    - a two-entry reviewed phrase map for the Feross banners (`is-buffer`, `buffer`).

    Comments that name nothing are printed as a note: at v3.7.21 that is the inline coi-serviceworker MIT notice, upstream's own code, whose text is in the linked `*.LICENSE.txt`. Every installed copy that a banner names is listed (over-inclusion is allowed).
  - **Entries, by the ADR-0010 precedence.**
    1. An upstream workspace without a licence file is AGPL-3.0-or-later, with a `source.html` pointer and a note when `package.json` declares something else.
    2. A package (or workspace) with root-level `LICENSE*`/`LICENCE*`/`COPYING*`/`NOTICE*` files, matched case-insensitively and regular files only, gets each file's full text. Line endings are normalized and a BOM is dropped. The text comes from the copy of exactly that version.
    3. Next comes an exception's `noticeText`, with its evidence and reason.
    4. Next, a usable declared licence: a valid SPDX expression without `WITH` whose every ID has a standard text. It gets the exact marker line, the declared author, contributors and repository (each collapsed to one line, or `not declared`), and the standard text of each ID.
    5. Anything else fails, naming `<name>@<version>`, and nothing is written. The output is written to a temp name and renamed.

    A licence text or `noticeText` that contains a `Package: x@y` line would forge an entry, so it fails the step, naming the package.
  - **Format.** A preamble, then `====…` separator, `Package:`, `License:`, a blank line and the body, sorted by `name@version`. There are no local paths in the file.
  - **Command.** `corepack yarn workspace web-build notices <upstream-tree> --bundle <dist> --out <file> [--exceptions <file>]` (default exceptions: `packages/web-build/license-exceptions.json`).
  - **Build and verify.**
    - `build` now runs `notices` (tree = work dir, `--bundle` = the built dist, out = `<dist>/third-party-notices.txt`), then `overlay`, `verify`, `package`. So the file is in the tarball and in `bundle-manifest.json` `files`.
    - `source.html` links `./third-party-notices.txt` only when the file exists, above the webpack `*.LICENSE.txt` list, which stays.
    - `verify` names `third-party-notices.txt` when it is missing, and `source.html` when that is missing or doesn't link the file.
- **Standard SPDX texts: source and licence.** I chose the npm route that the ADR-0010 amendment allows: **`spdx-license-list@6.12.0`** (Sindre Sorhus).
  - **Licence and size.** It is **CC0-1.0** (allow-listed; `check:licenses` lists it as `allowed`), has no runtime dependencies, and holds 728 `licenses/<SPDX ID>.json` files with `licenseText` taken from **SPDX License List 3.28.0 (2026-02-20)** (its readme). Unpacked size is 10.1 MiB, in `packages/web-build/node_modules`.
  - **Pin.** It is pinned exactly in `packages/web-build/package.json` and by the `yarn.lock` checksum. Published 2026-07-24, it passes `npmMinimalAgeGate: 1w`. I checked the tarball's npm shasum (`20b9ae77c3410ad08720bcd5cf562e9d4eeebadb`) before adding it.
  - **Offline.** Texts are read from the installed package (`createRequire` from `packages/web-build/package.json`, IDs matched case-insensitively through a directory index, so no path is built from untrusted input). Nothing is fetched at build time.
  - **Why npm and not vendored texts.** Vendoring `license-list-data` would commit 1 KiB+ texts that `check:no-upstream-copy` could flag. It would also need its own licence review. The npm route keeps the texts out of the repo and under the same `check:licenses` gate as any dependency.

  - `packages/web-build/README.md`: `notices`, the `verify` change, and the three repository checks.
  - Root scripts `check:licenses` and `test:optin:notices` (QA's suggestion; not part of `test`).

## ADR deviations
None. Interpretations within the contracts, for the lead's review:
1. **Operators.** SPDX operators must be upper case: `MIT and ISC` is not an expression. This is the SPDX/npm rule; none occurs in either tree.
2. **`WITH`.** An expression with `WITH` is never allow-listed (ADR-0009 A8). In the notices it is not "usable", because `spdx-license-list` carries licence texts, not exception texts, so such a package needs an exception with a `noticeText`.
3. **`License:` of a package with licence files but no declared licence.** It shows the exception's established licence if there is one, else `UNKNOWN` (the format contract's fallback word). None exists at the pin.
4. **Unneeded or unused exceptions.** An exception for an allow-listed package is a note, not a failure; an entry for an uninstalled package is a note (contract: "not an error, recommended: report as stale").

- **`check:pin` alias hole (new finding, not in scope).** The rule reads the package name from `resolution:`. A `resolutions` alias such as `"@joplin/lib": "npm:other-pkg@3.7.1"` resolves to `other-pkg@npm:3.7.1`, which no `@joplin/*` rule sees. A cheap, fail-closed fix: any lockfile key whose descriptors name `joplin`/`@joplin/*` must resolve to the same name. Suggest adding it with the first `patches/` story, which touches this rule anyway.
