### R3: `deploy/web/notestead-web-entrypoint.sh` (M1-AC34, review M1-S4-r1 nit 6)
- **Choice: normalise** (strip trailing `/`s), not refuse. Reasons:
  - `http://host:22300/` and `http://host:22300` are the same server (the WHATWG URL serialiser adds the `/` itself), and users paste URLs with a slash; refusing it would be a sharp edge with no security benefit.
  - It is what the entrypoint already does for `JOPLIN_SERVER_PUBLIC_URL`, and what the headless supervisor does for its own `JOPLIN_SERVER_URL` (`packages/headless/src/config.ts`), so the project treats the variable the same everywhere.
  - ADR-0002 and `deploy/web/README.md` define the value as `scheme://host[:port]`; stripping keeps exactly that. The review offered both; the test accepts both.
- Implementation: a shared `strip_trailing_slashes` helper (replacing the inline loop for `JOPLIN_SERVER_PUBLIC_URL`). For `JOPLIN_SERVER_URL`: `http_url` check → strip → `http_url` check again → the existing credentials/path/query check. So `http:///` collapses to `http:` and is refused with 64 naming the variable; `http://h/a/` is still refused as a path; `http://h//` is accepted as `http://h`. `JOPLIN_SERVER_PUBLIC_URL` gets the same re-check after stripping (before, `https:///` collapsed to `https:` and derived a bogus `JOPLIN_SERVER_HOST` of `https:`).
- The startup banner prints the normalised URL. `deploy/web/README.md`'s table says trailing `/`s are removed.
