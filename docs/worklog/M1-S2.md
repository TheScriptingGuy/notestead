## Approach
- **One entry point**, `packages/web-build/bin/web-build.ts`, run by Node type stripping. The workspace scripts `overlay`, `verify`, `package` and `build` are `node bin/web-build.ts <command>`. `src/webBuild.ts` parses the arguments (`node:util` `parseArgs`, options before or after the positional) and returns 0 for success, 1 for a failure and 2 for a usage error. Every failure message names its path.
- **Overlay** (`src/overlay.ts`, `overlay.json`, `overlay/`):
  - **Declarative rules.** Actions are `replace`, `replaceDir`, `remove`, `editJson`, `editHtml` and `generate` (with a `source` file or a built-in `template`).
  - **Two phases.** Every rule is checked and its result computed in memory first. All problems are reported together, each naming its path. Only then is `dist/` changed, so a failing overlay changes nothing.
  - **Fails loudly:**
    - every non-`generate` target must exist;
    - `generate` never overwrites a file;
    - `editHtml` needs exactly one `<title>`/`</head>`/`</body>`;
    - no edited or generated page and no `manifest.json` icon may reference a file the overlaid bundle won't contain.
  - **HTML edits are targeted text replacements.** Pages are never re-serialized, so the CSP `<meta>` and the `<script>` tags stay byte-identical.
  - **Rules applied** (the ADR-0010 table):
    - `environment.js`: replaced by ours (`__DEV__ = false`, plus the `exports`/`process.env.EXPO_OS` globals).
    - `icons/`: replaced by our **placeholder** set (SVG plus PNG 64/192/256/512, under the file names the upstream pages link).
    - `screenshots/`: removed.
    - `manifest.json`: our `name`/`short_name`/icons/`background_color`, and `screenshots` deleted.
    - The three HTML pages: our title, a description (and `og:description` where upstream has one) with the "not affiliated with JOPLIN SAS" notice, `<link rel="license" href="./source.html">`, our stylesheet, and a fixed "Source" link with an `aria-label`.
    - `notestead-overlay.css`: generated.
    - `source.html`: generated (`src/sourceOffer.ts`). It contains the upstream repo, tag and exact commit link; our repo and exact commit link; the build recipe; links to both licences and the AGPL text; links to webpack's `*.LICENSE.txt` files; and the trademark notice. A dirty working tree is stated on the page.
- **Our repository URL** comes from `NOTESTEAD_SOURCE_REPO` or the `origin` remote (`src/provenance.ts`). The value is normalized to `https://host/path`, and any `user:password@` is stripped so a credential in a remote can never reach the page. Our commit is `git rev-parse HEAD`, and `dirty` comes from `git status --porcelain`.
- **Verify** (`src/verify.ts`):
  - It takes the sha256 of every blob under `upstream:packages/app-mobile/web/public/icons` at `web.commit` and hashes every regular file of `dist/` at any depth (`src/tree.ts`). A symlink or special file is an error, not skipped.
  - The upstream tree is either `--upstream` or the cached blobless fetch from `check:no-upstream-copy` (`ensureUpstreamTree`; git lazily fetches only the blobs it reads). An empty icon set fails, so there is no vacuous pass.
  - It also checks the other two ADR-0010 verify items:
    - `environment.js` byte-equal to the overlay's file (instead of executing bundle code);
    - the CSP `<meta>` byte-equal to upstream's `index.html` at `web.commit`.
- **Package** (`src/packageBundle.ts`):
  - **Tarball.** GNU `tar --format=posix` gets the exact sorted file list on stdin (`--null --verbatim-files-from --no-recursion`), so the tarball and the manifest list the same files. Owner is set to `0:0` (no local user name leaks) and `--mode=go-w`. File mtimes are kept on purpose, because Caddy's ETag uses mtime+size (M1-S4).
  - **zstd** comes from **Node's built-in `zlib.createZstdCompress`** at level 9 with the frame checksum on (see Decisions). The tarball is written to a temp name and renamed last, and nothing is written when `dist` is missing.
  - **Manifest and sums.** `bundle-manifest.json` holds `upstream{repo,tag,commit}`, `notestead{commit,dirty}` and `files[{path,sha256,size}]` sorted by path. `SHA256SUMS` is in `sha256sum` format.
- **Build** (`src/build.ts`):
  - **Checkout.** `git init` + `git fetch --depth 1 --no-tags <web.repo> <web.commit>` + `git checkout --force --detach <commit>` into `--work` (default `~/.cache/notestead/web-build/<commit>`). An existing checkout at the commit is reused, and a stale `web/dist` is removed.
  - **Recipe.** It runs the official recipe unmodified: `corepack yarn install`, then `corepack yarn web` in `packages/app-mobile`, with `SKIP_ONENOTE_CONVERTER_BUILD=1 COREPACK_ENABLE_DOWNLOAD_PROMPT=0`. Each command is echoed with its environment overrides. The child environment drops the `npm_*`/`YARN_*`/`BERRY_*`/`INIT_CWD`/`PROJECT_CWD` variables that yarn injects into our own workspace script, so upstream's yarn configures itself.
  - **Finish.** `overlay`, then `verify` (against the checkout itself, no extra fetch), then `package`.
  - **arm64.** It refuses unless `NOTESTEAD_ALLOW_ARM64_WEB_BUILD=1` (the same variable as QA's T90 interlock). With it, the S1 conditions are added: `BUILD_SEQUENCIAL=1`, `NODE_OPTIONS=--max-old-space-size=3072` (ADR-0001 §3b).
  - **Testing.** The command runner is injectable. Unit tests run the whole `build` against a local `file://` upstream-like repository, with a fake runner standing in for `yarn install`/`yarn web`.
- **Branding assets.**
  - `overlay/icons/icon-vector-large.svg` is our own placeholder (a house with note lines). The PNGs were rasterized from it with Playwright's installed `chromium_headless_shell-1223` (a throwaway script in `/tmp`, not committed). The procedure is documented in `overlay/README.md`, and `overlay.json` marks the set as a placeholder.
  - No upstream icon or text was used. I read upstream's `public/` files at the pin read-only, in the reference clone, to learn their anchors. The comments in our `environment.js` are our own wording.
- **Tooling.**
  - The `eslint.config.js` block "Web bundle overlay scripts" adds browser globals and `sourceType: script` for `packages/web-build/overlay/**/*.js`.
  - The root scripts `test:optin:real-dist` and `test:optin:build` run QA's opt-in files. They are optional per the test plan and not part of `test`.
- **Tests that exercise the new scripts** (review M1-S1 P3): `src/{html,overlay,provenance,verify,packageBundle,webBuild}.test.ts` (32 new Jest tests, shared fixtures in `src/testing/fixtures.ts`, all written from scratch), plus QA's acceptance suite.

## Decisions
- **zstd:** Node's built-in zlib zstd (`zstdCompressSync`/`createZstdCompress`).
  - It is available since Node 23.8 / 22.15, so it is inside our `engines` (>= 22.19). It is part of Node (MIT; zstd is BSD), so there is no new dependency.
  - Node 24.17 printed no warning.
  - The `zstd` CLI (1.5.7 on the Pi, preinstalled on GitHub runners) is only needed to *extract* (`tar --zstd -xf`, as the tests and M1-S4 do).
  - GNU tar is required to *create* the tarball. It is present on the Pi and on ubuntu runners.
- **zstd level 9.** Measured on the Pi on the 29.8 MB tar of the S1 v3.7.21 dist:

  | Level | Size | Time |
  |---|---|---|
  | 3 | 10.6 MB | 1.1 s |
  | 9 | 9.6 MB | 2.4 s |
  | 12 | 9.5 MB | 4.8 s |
  | 15 | 9.5 MB | 9.7 s |
  | 19 | 8.9 MB | 24.5 s |

  Level 19 saves 7 % for 10x the time.
- **Icon file names:** ours reuse the names the upstream pages and manifest link (`icon-64.png` … `icon-vector-large.svg`), so the pages need no icon-link edits. The upstream bundle JS references no `icons/` or `screenshots/` file: I grepped the S1 `*.bundle.js` and found only unrelated strings such as `@react-native-vector-icons`.

## Round 2 (review `docs/reviews/M1-S2-r1.md`, CHANGES_REQUESTED)
This section supersedes two statements above: the checkout reuse in Approach/Build, and `--mode=go-w` in Approach/Package.

### Fixes
- **C1 (major): a reused upstream checkout is restored before building** (`src/build.ts` `checkoutPinned`).
  - **Reuse.** When `<work>/.git` exists and holds `web.commit`, the fetch is skipped, but `git checkout --quiet --force --detach <commit>` and `git clean --quiet --force -d` always run. The build then refuses to start, naming the files, if `git status --porcelain --untracked-files=no` is not empty.
  - **Trade-off.** `clean -d` without `-x` keeps **ignored** files (the ~11 GB `node_modules`, upstream's build outputs), so rebuilds stay incremental. It removes untracked, non-ignored files, which webpack could otherwise pick up.
  - **Residual risk.** An edit inside an ignored file (for example under `node_modules/`), or a tracked file hidden with `git update-index --skip-worktree`/`--assume-unchanged`, is not detected. That takes a deliberate act. The clean path is a fresh `--work` (or `rm -rf` of the cached one).
  - **Recipe log.** After the recipe, `build` logs whether upstream's install or build changed tracked files (the reviewer's optional T90 evidence). It doesn't fail on that, because upstream's own recipe may legitimately rewrite tracked files on a non-CI machine.
  - **Test.** `webBuild.test.ts` "build restores a reused checkout…": after a first build, it edits the tracked `public/index.html`, adds an untracked `public/extra.js` and an ignored `node_modules/kept.txt`, then builds again. The artifact has the pinned content and no `extra.js`, and `node_modules` is kept. The fixture upstream repo now ignores `node_modules/` and `dist/`, as upstream does.
  - **Negative control:** with the old `build.ts` (`git show bdd1c4c~1:…`), the same test fails with `Expected substring: not "LOCALLY MODIFIED"`, which reproduces the lead's probe.
- **C3: tar modes are independent of the umask.** `--mode=u=rwX,go=rX` replaces `--mode=go-w`, so every entry is 0644, or 0755 when executable.
  - **Test.** `packageBundle.test.ts`: files at 0600/0660/0700 are packed as `-rw-r--r--`/`-rw-r--r--`/`-rwxr-xr-x`.
  - **Negative control:** with `--mode=go-w` the test fails with `Received: "-rw-------"`.
- **P1: `sourceOffer.test.ts` (4 tests).**
  - the exact-commit links of both repositories, the recipe, both licences and the AGPL link;
  - the dirty-tree note only when dirty;
  - the empty-licence-list text;
  - escaping of pin and repository values (`<script>`, `&`).
