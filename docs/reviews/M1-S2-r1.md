## Summary
The overlay, verify and package code is careful, well structured work, and my re-runs reproduce every number in the worklog and QA's results.
- The overlay works in two phases and never re-serializes HTML, so the CSP and script tags stay byte-identical.
- Packaging feeds tar a NUL-separated file list, so the tarball and the manifest list the same files.
- The placeholder icons are clearly our own.
- No dependencies were added, and nothing was copied from upstream.

One **major** finding blocks approval. `build` reuses a cached upstream checkout without checking that its tracked files are clean. A locally modified upstream tree is then built and shipped while `bundle-manifest.json` and the AGPL §13 offer in `source.html` say "unmodified upstream at `web.commit`". The fix is small. The other findings are nits and can be follow-ups.

## Code findings

### C1 (major): `build` builds a modified upstream checkout and labels it as the pinned commit
- **Where:** `packages/web-build/src/build.ts:76-79` (`checkoutPinned`). With the default `--work`, the checkout lives in `webBuild.ts:115` (`~/.cache/notestead/web-build/<commit>`).
- **Problem:** if `<work>/.git` exists and `HEAD` equals `web.commit`, the checkout is reused as is. Nothing checks `git status`, and the `checkout --force` step is skipped, so tracked-file changes in the work tree go into the bundle. Meanwhile:
  - `bundle-manifest.json` records `upstream.commit = web.commit`;
  - `source.html` states "built unmodified from the upstream source below" (`sourceOffer.ts:47`).

  `verify` doesn't catch this. It reads the upstream CSP and icons from git objects, not from the work tree, so a changed JS source passes.
- **Probe (reproduced):** `/tmp/m1s2-review/probe/probe.mts` calls `buildUpstreamBundle` against a local `file://` repo with a fake recipe that copies `packages/app-mobile/src.txt` into `dist/app.bundle.js`.
  - First build, then edit the tracked `src.txt` in the work dir, then build again.
  - Output: `build: reusing the checkout of ebb8fa5… in …/work`, then `bundle content: LOCALLY MODIFIED`.
  - `git status --porcelain` in the work dir shows ` M packages/app-mobile/src.txt`.
- **Failure scenario:** the architect's status note invites an opt-in T90 run on the Pi. While debugging the nested-`corepack yarn` risk, a developer edits a file under `~/.cache/notestead/web-build/e41516e…/packages/…`. Weeks later a normal `build`, or the M1-AC28 import of that locally packaged artifact, ships the edited bundle.
  - The artifact's provenance and the §13 Corresponding Source offer are false.
  - In effect a silent local fork, which the "reuse, never fork / changes only via `patches/`" rule forbids.

  The code already marks *our* tree as dirty (`notestead.dirty`). The upstream side needs the same care.
- **Expected fix:**
  - On reuse, still run `git checkout --quiet --force --detach <commit>`. This is cheap and restores tracked files; untracked `node_modules` stay, so the incremental reuse still works.
  - Then fail, naming the files, if `git status --porcelain --untracked-files=no` in `<work>` is not empty.
  - Add a unit test in `webBuild.test.ts`: modify a tracked file between two `build` runs and assert that the artifact holds the pinned content, or that the run fails.
  - Optional, as T90 evidence: log `git status --porcelain --untracked-files=no` after the recipe, so the first CI run shows whether upstream's install or build rewrites tracked files (for example `yarn.lock` without immutable installs on the Pi).

### C2 (nit): `verify` hash-checks icons only; removed screenshots are not checked
- **Where:** `packages/web-build/src/verify.ts:19-29` (the denylist is `public/icons/*` only).
- **Problem:** M1-AC7 asks only for icons, so this meets the AC. But the screenshots (`public/screenshots/{tall,wide}.png`, upstream UI with its branding) are kept out only by the `remove` rule in `overlay.json`.
- **Failure scenario:** a later `overlay.json` edit drops or renames the `screenshots` rule. `verify` and `build` stay green, and the artifact ships upstream screenshots. QA's T53 checks only `overlay`'s own output.
- **Expected fix (follow-up, with a QA NEG):** derive the denylist from every binary asset the overlay replaces or removes, not just `icons/*`. A natural place is M1-AC29 or the M5-AC1 scan.

### C3 (nit): tar file modes depend on the builder's umask
- **Where:** `packages/web-build/src/packageBundle.ts:38` (`--mode=go-w`).
- **Problem:** `go-w` only clears bits. A builder with umask 077 produces 0600 entries owned by 0:0.
- **Failure scenario:** in M1-S4, the non-root `web` container can't read the extracted files. The same dist also packs to different bytes on different machines.
- **Expected fix:** use `--mode=u=rwX,go=rX`, which gives 0644 regardless of umask (executables keep `x`). M1-S4's importer could normalize modes instead.

### C4 (nit): `--work` is used without a guard, and work trees are never cleaned
- **Where:** `packages/web-build/src/build.ts:80-89` and `webBuild.ts:115`.
- **Problem 1, unguarded `--work`:** `--work` pointing at an existing, unrelated clone gets a `git fetch` plus `checkout --force`. Uncommitted changes are discarded and ~11 GB of `node_modules` are dropped into it. The likeliest target is the read-only reference clone, `~/joplin-web-app-work/upstream-joplin`.
- **Problem 2, no cleanup:** each pin bump leaves another ~13 GB `~/.cache/notestead/web-build/<commit>` behind, and nothing prunes old ones. On the Pi that adds up quickly.
- **Expected fix:**
  - Accept only an empty dir, or one marked as created by `build` (a marker file).
  - Prune other commits' work dirs, or document the cleanup in the README.
  - This combines well with the disk-space preflight already listed in the worklog's follow-ups.

**Credit:**
- **Process spawning:** argument arrays, no shell, a `-` guard on `web.repo`, and `GIT_TERMINAL_PROMPT=0` reused.
- **The arm64 interlock** refuses before anything is created.
- **The overlay**:
  - checks everything before any write, and fails loudly on missing, ambiguous or dangling anchors;
  - never lets `generate` overwrite a file;
  - targets HTML edits precisely, so the CSP stays byte-identical, which I confirmed against upstream `index.html` at `e41516e`.
- **Symlinks and special files** are errors, never skipped, so `verify` can't pass vacuously.
- **`verify` fails on an empty icon set**, and it reads the upstream CSP and icons from git objects at the pin.
- **`source.html`:**
  - carries the upstream repo, the exact commit link, the recipe and the upstream `LICENSE` at the commit;
  - carries our repo, exact commit and `LICENSE` (it exists at our root), plus the AGPL link and the trademark notice;
  - escapes every value;
  - strips credentials from the `origin` URL.
- **The packaging** is close to deterministic: sorted list, owner 0:0, a pax header name without a PID, atime and ctime deleted, and a temp-then-rename write.
- **The icons** are a house with note lines (I looked at `icon-192.png`), not derived from upstream.
- **`environment.js`** uses our own wording.
- **Licensing:** there is no new dependency; zstd comes from Node's built-in zlib.
