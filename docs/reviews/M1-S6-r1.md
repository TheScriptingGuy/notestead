- **Scope.** Branch `feat/M1-S6-test-harness` at `7907824`, against `main` `e8394b5`.
- **What was built.** QA built the harness: the compose test stack, the real-server guard, the fixtures, the redacting reporter and the self-tests. The engineer delivered R1–R4: the lint sleep ban, the PID-1 warning, trailing-slash normalisation and the README fix.
- **Result.** Every acceptance criterion (M1-AC18/19/20/34) and follow-up (F1–F5) is met on arm64, and my re-runs match the worklog and QA's results.
- **Strengths.** The harness proves its own claims, in particular:

  - the reporter's secret list (C1);
  - the lint-ban gaps (C2).

## Rulings on the points raised
- **One stack per run (QA Interpretation 1): accepted.** It is the only way "healthy before any test starts" holds literally, and isolation stays per test (user, headless project and volume, BrowserContext). It is still a change to ADR-0007 §Fixtures and isolation (per-worker `joplinServer`, `clearDatabase` in worker teardown), so the architect must record it (C3).
- **`headless` → `headlessService`: accepted.** Playwright reserves `headless`. The architect records the rename in ADR-0007 and in the M1-S6 goal line (C3).
- **podman-compose workarounds: accepted.**
  - Self-polled health with fail-fast on `unhealthy`/exited/unchecked: podman-compose 1.3.0's `podman wait` never returns for a service that stays unhealthy.
  - String (CMD-SHELL) healthchecks: list values are appended on merge, strings replace.
  - `x-podman: {in_pod: false}`: a pod would share the network namespace with `web`.

  Each is documented, `docker compose` ignores the `x-` key, and M1-S8 must confirm podman healthcheck timers on the runners, as the plan says.
- **Chromium r1223 through `executablePath`: accepted.** No download, CI uses Playwright's own browser, and the residual risk (Chromium 148 on the Pi, 147 in CI) is written down.
- **R3, normalise instead of exit 64: accepted.**
  - It matches `JOPLIN_SERVER_PUBLIC_URL` and the supervisor's own handling.
  - Re-running `http_url` after stripping closes the collapse cases (`http:///` → 64; `/a/` → `/a` → refused as a path).
  - The `JOPLIN_SERVER_PUBLIC_URL` re-check is a real fix: `https:///` used to derive the bogus host `https:`.
- **D5 (lint misses `promisify(setTimeout)` and aliasing): follow-up, not a blocker** (C2). R1 as specified is fully met and proven. No such form exists in the repository (lint is clean). Code review remains the backstop for ADR-0007's no-sleep rule. Closing it test-first needs a QA fixture before the engineer's selector, so it belongs in a small item before M1-S7, not in a fourth commit cycle here.
- **Harness security:**
  - **Guard (M1-AC19): sound.** It accepts only `http://127.0.0.1|localhost:<port>` with no credentials, path or query. That port must be the published `22300` of a running container with the stack labels, and podman is the only thing asked. It runs in `newStack`, in the worker `stack` fixture and in the contract globalSetup, before the sweep. No other code path takes a server address from the environment: `web`, `headless` and the device have their upstreams hard-coded to stack service names.
  - **Redaction (M1-AC20): sound for what the AC names.** The fixtures redact what they attach. The reporter, listed first, rewrites every attachment file and the trace zip entry by entry. I confirmed in `node_modules/playwright/lib/reporters/html.js:116` that the HTML reporter copies only in `onEnd`. Unredactable attachments are dropped. My own scan of every artifact of QA's verify run found 0 leaks (details below). One gap for the future is C1.
  - **Can `web` reach the headless Data API? No.** The CLI binds `api.port` on `127.0.0.1` inside the headless container's own network namespace. No pod is used: `in_pod: false`, and ac18 asserts `pod: ''` for every service. From `back`, `web` can reach only the supervisor's `/healthz` on `:8090` (`0.0.0.0`), which is the ADR-0006 design.
  - **Secrets in logs: clean.** Passwords travel only as compose secret files (mode 0444 in a fresh 0700 `mkdtemp` tree) and on the device's stdin. Every compose, device and container log is redacted with the known secrets, and the Data API token is read inside the container only to redact it. C4 and C5 cover two places where throwaway secrets sit at rest.

## Code findings
**C1 (minor). `tests/e2e/support/redactingReporter.ts:11-23`.** The reporter gets its known secrets only from `NOTESTEAD_E2E_STACK`, which globalSetup sets once.
- **Problem:** that covers only the *default* account. The passwords and master passwords of per-test accounts (`e2eeAccount`, created in the worker, `tests/e2e/support/fixtures.ts:112`) and the per-test Data API tokens never reach the reporter. The fixtures redact their own attachments with the worker's full list. The Playwright trace, however, is redacted *only* by the reporter, and so are `error-context.md` and the `result.errors` and `stdout` text that ends up in JUnit and HTML (the reporter doesn't touch those at all).
- **Failure scenario:** in M1-S7 the walking skeleton types the per-test E2EE master password into the web app. The trace's action parameters and DOM snapshots then carry it unredacted into `trace.zip` and `playwright-report/`, which CI uploads on every run (strategy §7). The values are throwaway, but the test plan's claim ("every account/master password … the stack knows") would be false. M1-AC20's self-test doesn't catch this, because it never puts a per-test secret into the browser.
- **Expected fix (QA, before or in M1-S7):**
  - Give the reporter the per-test secrets, for example a 0600 `secrets.jsonl` in the stack work dir, appended by `createAccount` and `upHeadless` and read in `onTestEnd`.
  - Also redact `result.errors[].message/stack` and the `stdout`/`stderr` chunks.
  - Extend the M1-AC20 self-test to fill a per-test secret into a page input, so the trace carries it.

**C2 (minor). `eslint.config.js:200-210`.** The F1 ban matches only direct calls and fixed member forms. My `eslint --stdin` probe as `tests/unit/probe-review.mjs` reported only the namespace import. It did **not** report:
- `promisify(setTimeout)`;
- `const alias = setTimeout; alias(r, 10)`;
- `const { setTimeout: st } = globalThis`;
- `globalThis['setTimeout'](r, 10)`;
- `new Promise(r => setInterval(r, 10))`.

**Failure scenario:** `const sleep = promisify(setTimeout); await sleep(500)` is the most common Node sleep idiom after the Promise wrapper. It would pass lint in a new E2E spec.

**Expected fix (QA fixtures first, then the engineer):**
- QA adds NEG fixtures `F1-T02-promisify`, `-alias`, `-destructure` and `-computed`.
- The engineer bans `setTimeout` used as a value, for example `Identifier[name="setTimeout"]:not(MemberExpression[computed=false] > Identifier.property):not(Property > Identifier.key)`, plus `MemberExpression[computed=true][property.value="setTimeout"]`.
- The `req.setTimeout` positive control must stay green.
- Owner: QA and the engineer, as a small item before M1-S7.

**C3 (minor, ADR conformance). `docs/adr/0007-test-strategy-and-harness.md:51-56`.** The harness differs from ADR-0007 in three ways, and the ADR has not been amended:
1. one stack per run instead of a per-worker `joplinServer`, with no `clearDatabase`;
2. the fixture name `headlessService`;
3. `e2eeAccount` seeds a folder and one note only, while ADR-0007:56 says it "also seeds a to-do with `todo_due`, a tag and an attachment". This difference is recorded nowhere: it is missing from the plan's Interpretations and from Out of scope.

**Failure scenario:**
- The first M2 or M4 test that relies on the documented seeded to-do or tag finds none.
- Once CI runs more than one worker (`playwright.config.ts:21`), a test that disrupts the shared stack breaks the tests running in parallel. The ac20 self-test, which stops the server (`attachments.spec.ts:44`), is an example.

**Expected fix:**
- **Architect:** amend ADR-0007 §Fixtures and isolation with one stack per run, `headlessService`, and the rule that a test which stops or reconfigures a shared service runs in a serial project or on its own stack. Also update the M1-S6 goal line in `docs/backlog/M1.md`.
- **QA:** record the seeding gap in the plan and add the to-do, tag and attachment when the first story that asserts on them arrives (M2 or M4).

**C4 (nit). `tests/contract/support/podman.ts:173-174`, with `tests/contract/support/globalSetup.ts:19`.** `removeLabelled()` now sweeps every resource carrying the test label with *any* value, `stack` included.
- **Failure scenario:** a developer runs `node tests/stack/cli.ts up` and then any contract suite. The contract globalSetup destroys the dev stack, even when `JOPLIN_SERVER_URL` names it: the guard accepts it, then the sweep removes it. The descriptor is left behind in `/tmp`.
- **Expected fix (QA):** keep the global sweep at `=contract`, and sweep `stack` resources only when no live descriptor claims them.

**C5 (nit). `tests/stack/stack.ts:235-248` and `tests/harness/selftest/attachments.spec.ts:70-76`.** Two places hold throwaway secrets at rest in plaintext:
- The stack descriptor in `/tmp/notestead-stacks/` holds the account passwords. `mkdirSync({recursive, mode: 0o700})` doesn't correct a directory that already exists with another owner or mode, and `attachStack` trusts whatever JSON is there.
- `planted.json` holds the passwords and the Data API token under `test-results/`, which CI uploads on every run.

**Failure scenario:** on a shared host, another user pre-creates the directory and reads or plants descriptors; on CI, the M1-S6 self-test's `planted.json` becomes a public artifact. Both hold values of destroyed containers only, so this is hygiene, not exposure.

**Expected fix:**
- QA: use a per-user directory (`$XDG_RUNTIME_DIR`, or `test-results/stack/`) or check owner and mode.
- CI-CD (M1-S8): exclude `**/planted.json` from uploads, or have QA write it outside `test-results/`.
