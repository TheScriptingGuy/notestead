## Code findings

1. **minor** `.github/workflows/e2e.yml` (step `id: network`, `changed()`): `git diff ... 2>/dev/null | grep -qx` treats a git failure (a missing base commit, a shallow fetch problem) as "pin unchanged". The result is a silent `network tests: excluded` on exactly the pin-bump run that should include them. Failure scenario: a force-pushed branch whose `before` is not fetchable and whose `merge-base` fails falls back to `$GITHUB_SHA~1`, which can miss a pin change in an earlier commit of the push. Fix (follow-up): on diff failure, fail open (include network tests) and say so in the step summary.
2. **minor** `e2e.yml` (known, the planner's note): a bump PR's final head only gets the network tests through a manual `workflow_dispatch` with `network: true`. `pull_request` does detect a pin change, so the PR run itself does include them. Residual risk: later pushes that don't touch the pin file. The worklog documents the dispatch instruction. Accepted.
3. **nit** `tests/fixtures/plugins/repeating-todos/`: the plugin's LICENSE is GPL-3.0 but its `package.json` says MIT. `provenance.json` records this and notes both are AGPL-compatible. The user is aware. The `.jpl` sha256 (`df95494a...`) and the LICENSE sha256 (`d3b74b0a...`) both match `provenance.json` when recomputed. This is a binary fixture of the user's own plugin, with a source offer and no upstream Joplin source copied, so "Reuse, never fork" is respected. No secrets or real note content found (grep of the specs and support files for `token=` and passwords came back empty).
4. **nit** `tests/fixtures/m1-s5/device/batch.mjs`: good fix. It cites `command-sync.ts:163` for the lock race and uses `sync --use-lock 0` only for the second sync. It is unit-tested by `device-batch.test.mts`.

CI/CD checklist for CC-NET: permissions remain `{}` at workflow level. Event data enters through `env`, not through script interpolation. There is no `pull_request_target`. Actions are still SHA-pinned (`check:workflows` confirms). No publish path is touched, and nothing reaches secrets or a self-hosted runner. The schedule trigger runs only on the default branch, as intended.

ADR conformance: ADR-0011 is Proposed (not Accepted), and no implementation depends on it. Plugin support on web is validated only for the `.jpl` and repository flows, with no patches added. The user's decisions are recorded in STATUS.
