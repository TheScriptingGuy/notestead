## Summary
The product change is one 8-line CSS rule (`67e04a3`) that reserves an 18px strip so the Source link never covers upstream

re-ran green on my side. x64 and the CI-built bundle (RU-7) remain PENDING-CI, as agreed; that is merge evidence, not a blocker

## Code findings

1. **minor** `packages/web-build/overlay/notestead-overlay.css:6`: `body > #root { height: calc(100% - 18px) }` leaves a strip
   showing the page background (upstream's `index.html` sets none, so default white), also under a dark theme or on a
   notched or home-indicator device. Failure scenario: dark theme shows a light 18px band at the bottom edge. Fix (follow-up,
   not blocking): give the link/strip an explicit background, or check the look in dark theme; consider `env(safe-area-inset-bottom)`
   if the link is made taller on touch devices. `html`/`body` height is not set by us; the rule relies on `#root` having a
   resolvable percentage height, which the 10 green E2E runs confirm for the pinned build, but a future upstream change to
   body/root sizing would only be caught by the ADR10 tests (they exist, good).
2. **minor** placement coverage: `M2-S6-ADR10-01/-02` visit five states (list, side menu, viewer, editor, Configuration).
   App modals/dialogs (react-native-web `Modal` is portalled to `body`, outside `#root`) are not covered, so a full-screen
   dialog button at the bottom-left could still sit under the fixed link. Fix: note as a follow-up state in the ADR10 test or
   confirm the link's z-index relative to modal overlays.
3. **nit** worklog follow-up is right: `web-build overlay` is not idempotent, so a CSS-only change needs a manual swap. Not in scope.

Credit: the fix reserves space structurally rather than relying on an empty corner; the selector is scoped to `index.html` only;
no ADR deviation.
