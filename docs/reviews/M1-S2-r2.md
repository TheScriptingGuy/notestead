## Code findings

### R2-C1 (major): `build` deletes user files in a non-empty `--work` it didn't create (regression from `bdd1c4c`)
- **Where:** `packages/web-build/src/build.ts:93-104`.
  - For a directory without `.git` it runs `git init`, `fetch` and `checkout --force`, then the new `git clean --quiet --force -d`.
  - For any directory with `.git` it skips straight to `checkout --force` and `clean -d`.
  - Nothing checks that `--work` is empty, or that an earlier `build` created it.
- **Probe (reproduced):** `/tmp/m1s2-review/probe/probe2.mts`, with a fake recipe and a local `file://` upstream.
  - `--work` holds a pre-existing `precious/notes.txt`.
  - At `0b9199f`, after `build`: `precious/notes.txt still exists: false`.
  - With the `src/` tree from `bdd1c4c~1`: `true`.
- **Failure scenario:**
  - The test plan and `ac5-build.optin.mts:11/40` invite `NOTESTEAD_BUILD_WORK=<dir with ~15 GB free>` and pass it directly as `--work`.
  - Someone sets it to a mount point or to `~/joplin-web-app-work`.
  - `build` turns that directory into a git repo and deletes every untracked, non-ignored file under it. For example, `spikes/` holds the S1 dist that T95 depends on. Nested git repos survive only because `clean` has a single `-f`.
  - With `--work` set to the reference clone, uncommitted and untracked files there are destroyed too.
- **Expected fix (the guard half of r1-C4, now required):**
  - `build` writes a marker file (for example `<work>/.notestead-web-build`) when it creates a work dir.
  - It refuses, naming the path, any `--work` that exists, is not empty and has no marker. Only marked dirs are reused, checked out with `--force` and cleaned.
  - Add a unit test: a non-empty unmarked `--work` exits 1, names the dir and leaves its files untouched. Also add one positive control: a marked dir is reused.
  - Optionally, QA can change the T90 note to "an empty or new directory".
