## Code findings

1. **nit** `tests/e2e/support/swTimeline.ts` `activeVersionBefore`. It returns `''` when no `activated` event was seen before the load, and then (ii) "a version other than `''` reached activated" is satisfied by any activated version. Scenario: if CDP did not replay the old worker's state before `t`, a wrong version could pass part (ii). The later unchanged assertions (bundle marker, cached digest, B's files fetched) still gate the test, so it cannot give a false pass, but a one-line guard (`unknown` when `previousVersionId === ''`) would make it strict by itself.
2. **nit** `tests/e2e/m2-s5/upgrade.spec.ts` N branch drops the "exactly one reload line" check; that is right, since there is no line in (N), and (N) is classified only with zero lines (`swu-13`).

Checked, no weakening:
- **(N) signature** (`classifySelfReload` without a line) needs all four parts: no reload line; a version other than the previous one reached `activated` after the load started; no reload navigation requested; `GET /serviceWorker.bundle.js` answered 200 (a 304 is not enough, `swu-12`). Missing (ii) or (iv) gives `unknown`, naming the part (`swu-11/12`); a line present is never (N) (`swu-13`); no `load` argument gives `unknown`. After (N) the spec still requires, unchanged, the new `bundleMarker`, the cached digest of B's app bundle, B's files fetched with 200, the opened profile, and the data checks. In `sw-update.spec.ts`, (N) also requires `bundleMarker === expected` for that switch, and any other outcome still lands in `failures`.
- **Before-load allowance** (`beforeLoad.ts`, `ro-01..04`): only `GET /` and `GET /serviceWorker.bundle.js` pass; every other method or path (any PUT, a `GET` of a bundle file, a non-GET worker request) is named and fails. A GET carries no data to the container, and the purpose of the control (no sync, no write before the one online load) is intact. `ro-03/04` are the negative controls.
- **`waitUntil: 'commit'`** for the online load is paired with a 200/304 status assertion on the document response and a poll for the container's logged `GET /` after the log mark, so the load is proven to have reached the server; it only stops waiting on `load`, which upstream's self-reload can interrupt. This is the correct fix for the defect, not a relaxation.
- M2-AC16-03's control "the worker was updated" now accepts C, R (with the user reload judged as in r1) or N; each is a full signature or `unknown` fails.
- No `.only`, skip or `waitForTimeout` added (grep of the diff: 0). No upstream code, secrets or note content.
