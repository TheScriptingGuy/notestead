## Code findings

1. **minor:** static 404s carry no `Cache-Control` or site headers (`deploy/web/Caddyfile:99-111`).
   - **Problem:** a missing static file returns a bare `404` with no `Cache-Control`, COOP, COEP or `nosniff` header. Verified with `curl -D -` on `/missing.bundle.js` and `/icons/`. Proxied errors do keep `no-store, no-transform`: the 502 path was checked.
   - **Failure scenario:** with no `Cache-Control`, Cloudflare caches a 404 on a cacheable extension (`.js`) at the edge for a few minutes by default. Suppose a chunk name that 404s now becomes valid after an image upgrade, for example a renumbered `<n>.bundle.js`. Then browsers behind the tunnel keep getting the cached 404 until it expires, and the app fails to load a chunk. This goes against ADR-0006's intent that nothing from `web` is cached by the front. M1-AC12 only names 200 and 304 responses, so this is not an AC failure.
   - **Expected fix:** a `handle_errors` block on `:8080` that sets `Cache-Control: no-store, no-transform` and the site headers on error responses. Ask QA for a contract case: a 404 for a `.js` path carries `no-store`.
2. **minor (ADR gap, architect first):** `Cf-Access-Client-Id` and `Cf-Access-Client-Secret` are forwarded to the Joplin Server (`deploy/web/Caddyfile:64-65`).
   - **Problem:** the implementation strips exactly what ADR-0002 rule 3 names: `Cf-Access-Jwt-Assertion` and `Cf-Access-Authenticated-User-Email`, case-insensitively, as verified. My probe through `/joplin-server/api/ping` showed that the echo upstream still receives `Cf-Access-Client-Id: cid` and `Cf-Access-Client-Secret: csecret`. Rule 7 already treats the secret as a credential, since it is redacted in the logs.
   - **Failure scenario:**
     - A user puts the whole hostname behind a Service-Auth Access policy (ADR-0006 calls this possible), or a script sends its service-token headers to every path.
     - The service-token secret then reaches the Joplin Server.
     - It also reaches any reverse proxy in front of the server that logs request headers, because `JOPLIN_SERVER_URL` may be another proxy.
   - **Expected fix:**
     - The architect extends rule 3 to strip `Cf-Access-Client-Id` and `Cf-Access-Client-Secret` upstream on `/joplin-server/*`.
     - The engineer adds two `header_up -…` lines.
     - QA extends `ac10-c9`.
     - It can ride along with M1-S6 or M4 (`/mcp`).
3. **minor (M5 follow-up):** the image inherits the Caddy base's OCI labels (`deploy/web/Containerfile:10`).
   - **Problem:** `podman image inspect` shows the following labels on the built image:
     - `org.opencontainers.image.licenses=Apache-2.0`
     - `title=Caddy`
     - `source=https://github.com/caddyserver/caddy-docker`
     - `version=v2.11.6`
     - plus Caddy's `description`, `url`, `vendor` and `documentation`
   - **Failure scenario:** any published or shared Notestead image would claim to be Caddy under Apache-2.0, with Caddy's source repository. That is wrong licensing metadata for an AGPL-3.0-or-later image and points away from our source offer. Labels are M5 scope (test plan §Out of scope), so this is not a defect of M1-S4.
   - **Expected fix:** M5's label set (ADR-0006: `version`, `source`, `revision`, `licenses=AGPL-3.0-or-later`) must override **every** inherited `org.opencontainers.image.*` key, including `title`, `description`, `url`, `documentation` and `vendor`. The M5 image-inspect test should assert that no Caddy value remains. Record this in M5's backlog.
4. **nit:** unlisted directory members survive as empty directories (`packages/web-build/src/importBundle.ts:170-173`).
   - **Problem:** I appended `evil-empty/` and `evil-empty/deeper/` directory members to the QA artifact and rebuilt `SHA256SUMS`. `import` exits 0, and `out/evil-empty/deeper` exists. The test plan allows unlisted directory members, and an empty directory can't carry data (Caddy returns 404 for it), so the impact is nil. Still, it stretches "nothing outside `files` exists".
   - **Expected fix:** accept a directory member only if it is a prefix of a listed file. Alternatively, prune directories that hold no listed file before the rename.
5. **nit:** the decompression bound is declared by the artifact itself (`packages/web-build/src/importBundle.ts:131`).
   - **Problem:** the bound is computed from `files[].size` in `bundle-manifest.json`. That file is only checksummed by the `SHA256SUMS` beside it, so a crafted artifact can list huge sizes and lift the bound up to Node's `MAX_LENGTH` (2^53−1 here). The supplier of the artifact is trusted for content anyway, so this only matters for a corrupted or hostile file on the dev box (out-of-memory). A tarball bomb paired with an honest manifest is already stopped, and the unit test covers that case.
   - **Expected fix:** also cap the bound at a fixed ceiling, for example 1 GiB total. The real bundle is about 26 MB.
6. **nit:** a trailing slash in `JOPLIN_SERVER_URL` passes the entrypoint (`deploy/web/notestead-web-entrypoint.sh:44`).
   - **Problem:** `http://10.0.0.1:22300/` passes the check, because `*/?*` needs at least one character after the `/`. Caddy then exits 1 with its own adapter error instead of the entrypoint's named exit 64. It still fails closed.
   - **Expected fix:** strip trailing `/` as is done for `JOPLIN_SERVER_PUBLIC_URL`, or refuse any `/`. M1-AC34 (M1-S6) can include this case.
7. **nit:** `EXPOSE 8089` (`deploy/web/Containerfile:25`).
   - **Problem:** `podman run -P` would publish the internal listener. The listener's scope itself is correct: only `/joplin-server/api/*`, and `/JOPLIN-SERVER/login` on `:8089` is 404. Its exposure depends on M1-S6's compose topology.
   - **Expected fix:** M1-S6's compose file must not publish `8089`, and QA's M3-AC10 egress test should cover it. Optionally drop `8089` from `EXPOSE` and document it as internal.

## Merge policy (x64 PENDING-CI)

M1-S4 **may merge** with x64 at PENDING-CI, under these conditions:
1. **Why the definition of done allows it:** it requires x64 "CI when available", and no CI contract layer exists before M1-S8.
2. **Why the x64 risk is low:**

   - The only `RUN` (`setcap -r`) runs natively per architecture.
   - The fixture images (`node:22-bookworm-slim`, `joplin/server:3.7.2`) are multi-arch.
   - The import path is architecture-neutral Node code. Its acceptance suite runs on x64 in `ci.yml` after the first push.
3. **Conditions:**
   - `STATUS.md` records M1-S4 x64 as PENDING-CI with M1-S8 as the closing gate.

   - An x64 failure there reopens M1-S4.

## Out-of-scope observation (pre-existing, not counted in this verdict)

- **Broken source-offer URL in locally packaged bundles** (`packages/web-build/src/provenance.ts:22-27`, M1-S2/M1-S9 code).
  - The image built in my run serves a `source.html` whose Notestead source link is `https://github-notestead/TheScriptingGuy/notestead`.
  - The cause: `origin` is the SSH alias `git@github-notestead:TheScriptingGuy/notestead.git`, and the scp-style conversion turns the alias into an https hostname.
  - CI checkouts use `https://github.com/…`, so CI artifacts are unaffected. Every Pi-packaged artifact, including I90's real dist, carries a dead AGPL source link unless `NOTESTEAD_SOURCE_REPO` is set.
  - **Recommendation:** for the orchestrator to backlog before the M5 pre-publish checklist. Either reject non-resolvable alias hosts in favour of requiring `NOTESTEAD_SOURCE_REPO`, or derive the URL from the pin or a repo setting.
