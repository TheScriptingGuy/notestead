## Rulings on the focus questions
**1. Security of `e2e.yml`: sound.**
- **Triggers:** `push` (all branches, `paths-ignore: docs/**`), `pull_request` and `workflow_dispatch`. There is no `pull_request_target` or `workflow_run`, and the new `[forbidden-trigger]` rule now enforces that.
- **Same-repo pull requests** are skipped in the `bundle` job (`e2e.yml:40`), as in `ci.yml`. Because `test` needs `bundle`, the test jobs are skipped with it.
- **Fork PRs** get `contents: read`, no secrets, and GitHub-hosted runners only. A fork's `actions/cache/save` is scoped to `refs/pull/<n>/merge`, so it cannot poison `main`'s `web-bundle-…` entry.
- **Permissions:** `permissions: {}` at the top, and `contents: read` per job (`:26`, `:43`, `:146`). Both checkouts set `persist-credentials: false`.
- **Gate placement:**
  - The gate step (`:215-218`) is `if: always()` and comes after the contract and E2E steps.
  - The job summary and the upload require `steps.gate.outcome == 'success'` (`:221`, `:227`).
  - Both test steps run `!cancelled() && <prep succeeded>`. On a step timeout or a failure, the next layer and the gate still run. On cancellation, only `always()` steps run, which includes the gate.
  - A run that was killed has no `redaction-complete.json`, so the gate deletes what its pending marker lists (`tests/support/uploadGate.ts:174-190`).
  - If the gate itself cannot run (for example, setup failed and there is no Node 24), it exits non-zero and nothing is uploaded. That is the safe direction.
- **Upload content:**
  - `test-results/` and `playwright-report/`, plus `!**/planted.json`.
  - Hidden files stay out by default. The gate deliberately skips hidden paths (`uploadGate.ts:205`), so the default must hold, and `M1-S8-E08` guards it.
  - Descriptors with throwaway passwords live in `tmpdir()/notestead-stacks-<uid>`, which is outside the upload roots.
- **Expression interpolation in `run:`:** only `${{ matrix.runner }}`, a static matrix literal, so there is no injection path. Values from the pin and the bundle job go through `env:`.
- **Pins:**
  - Every `uses:` is a 40-hex SHA, with the same SHAs and version comments as the existing workflows.
  - I checked the PyPI hashes in `requirements.txt` against the PyPI JSON API:
    - podman-compose 1.3.0 `34599a9f…`, GPL-2.0-only;
    - python-dotenv 1.2.4 `42269a8a…`, BSD-3-Clause;
    - PyYAML 6.0.3 cp312 x86_64 `ba1cc08a…` and aarch64 `9149cad2…`, MIT.
- **Licence:** podman-compose is GPL-2.0-only. It runs as a CI tool and is never linked or shipped, the same status as shellcheck (GPL-3.0), so it raises no AGPL compatibility question.

## Code findings
- **C1 (minor)** `.github/actions/podman/action.yml:37-49`
  - **Problem:** when no user manager is reachable, the step enables lingering and polls up to 30 s for `/run/user/<uid>/bus`. It then exports `XDG_RUNTIME_DIR` and `DBUS_SESSION_BUS_ADDRESS` whether or not the socket appeared. A timeout is not reported.
  - **Failure scenario:** on the arm64 partner image, linger does not start `user@<uid>.service` within 30 s. The step still succeeds, podman points at a bus that does not exist, and it falls back to cgroupfs, so no healthcheck timer runs. The run then fails minutes later in globalSetup with the service `starting`. The root cause is two steps back, in a line that only says `is-system-running: offline`.
  - **Expected fix:** after the loop, if the socket is missing, emit `::error::no systemd user manager after enable-linger (healthchecks cannot run)` and exit 1, or at least a `::warning::`. While there, add the network backend to the "Record podman" line (`{{.Host.NetworkBackend}}`, plus `{{.Host.RootlessNetworkCmd}}` if podman 4.9 supports it), since netavark/pasta vs slirp4netns is the other likely 4.9 difference. The bounded poll itself is runner setup, not test synchronisation, so the ADR-0007 sleep ban does not apply.
- **C2 (minor; QA-owned)** `tests/contract/m1-s6/ac20-attachments.test.ts:133`
  - **Problem:** `expect(leaks).toEqual([])` prints each `Leak`, including its `excerpt`: 100 characters around the leaked value (`tests/support/redact.ts:209`).
  - **Failure scenario:** a redaction regression shows up first on a CI runner, which is what this test exists to catch. Jest then prints the leaked throwaway account and master passwords, the Data API token and the planted markers into the public job log. That log is not gated. Jest also writes them into `test-results/contract/jest-results.json`. There, the gate can redact only by the token and header patterns. The inner run's registry has already been removed, and the gate has no `nst(pw|mp)[0-9a-f]{24}` pattern.
  - **Impact:** the values are throwaway (a fresh user on a throwaway server in a discarded runner), so there is no real credential exposure. That is why this is not a major.
  - **Expected fix:** report leaks value-free, as `c1r1-realflow-secrets.test.ts:125` already does (`where: kind`). Optionally, add the harness password pattern to the gate's redaction as a second layer. Check the other leak or hit assertions for the same pattern.
- **C3 (nit)** `.github/workflows/e2e.yml:84-92`. On a cache miss, the `bundle` job records `df` before T90 but not after it (QA note a). X8 only comes from `web-bundle.yml`. **Fix:** an `if: always()` `df -h`/`free -m` step after `t90`, as in `web-bundle.yml`.
- **C4 (nit)** `.github/workflows/e2e.yml:9-10`. The header comment says the gate "deletes the throwaway passwords". It deletes the secret registries. The stack descriptors are removed by teardown and are never under the upload roots. **Fix:** reword it the next time the file is touched.
- **C5 (nit)** `eslint.config.js:28`. `noSleepMessage` is now also used for `scheduler` but still names only setTimeout/setInterval. The senior engineer flagged and deferred this. **Fix:** cosmetic, whenever the file is next touched.
