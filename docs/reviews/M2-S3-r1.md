## Code findings

1. **minor** (non-blocking, owner qa-specialist), `tests/support/l20Scan.ts:25-27`. The scan de-duplicates files by the hash of their content alone, across the whole run. Two tests that each write a value-free file with equal content would count once instead of twice. The files hold failures, console args and a storage estimate, so a collision is unlikely but possible, and an undercount is the wrong direction for a tie counter. Locally the `test` column also reads `stack` for every row, because the stack logs-dir copy (`test-results/e2e/stack/…`) sorts first and wins the de-dupe, so the column does not name the test. Fix: key on (test directory, hash), or prefer the `attachments/` copy over the `stack/` copy when both exist.
2. **minor** (non-blocking, owner qa-specialist), `tests/harness/tools/scan-l20.ts` and the L20 plan section. Run locally, the scan counts the injected fault of a sensitivity run (`sens/ws-sqlite-evidence`) as a qualifying occurrence (4 instead of 3 in the round's set). I judge this a documentation item, not a defect. In CI no `sens/` or `verify/` folders exist, and the plan says occurrences are recorded by hand locally. Fix: state in the plan and in the tool header that local counts include sensitivity runs, or skip paths containing `/sens/`.
3. **minor** (non-blocking, owner ci-cd-specialist with qa-specialist), `.github/workflows/e2e.yml:260-264`. The runner is named through a `$RUNNER_TEMP/test-results-e2e-<runner>` symlink because the tool has no runner env var. It works: the link sits outside the workspace, so the upload does not follow it, and the step is `continue-on-error`. It is a workaround of QA's tool inside the workflow. Fix when convenient: let QA add `NOTESTEAD_RUNNER` (or `--runner`) to `scan-l20.ts` and drop the symlink.
4. **minor** (non-blocking, owner ci-cd-specialist). The `if: always()` scan is acceptable and I do not require gating it on `steps.gate.outcome == 'success'`. It reads files before redaction, but it prints only the test directory name, rc, statement type and table, db, flags and the path, never bound values or console args. The summary is not an artifact, and a failed gate is exactly when the occurrence data is most useful. One residual: `l20-scan.json` is written to `test-results/` after the gate ran, so it is uploaded without the gate having inspected it. It is value-free by construction (`l20Scan.ts` header and rows). Fix: either leave it with a comment saying so, or write it outside `test-results/` and upload it as a separate path.
5. **nit** (non-blocking, owner qa-specialist), `scan-l20.ts:30-35`. Only the read is inside the `try`, but `scanL20` calls `JSON.parse` on each file outside it. A truncated `web-sqlite.json`, which a killed run can leave, ends the tool with a stack trace and a non-documented exit path. `continue-on-error` absorbs it. Fix: catch and report the file name, then skip the file.
6. **nit** (non-blocking, owner qa-specialist), `tests/e2e/support/sqliteFault.ts`. The `releaseReady` quiet period (1.5 s, three times the 500 ms save queue) is a measured-time condition used inside a poll, not a sleep, so it complies. It rests on upstream's 500 ms queue value. The test plan records this; a one-line comment at the constant would keep the dependency visible.

Credit: the fault script wraps only `Worker.prototype.postMessage`, keeps the bound title in page memory (compared in the page, only a boolean leaves it), and WSQ-01 proves the rollback from the worker's replies instead of a log line. WSQ-02 and WSQ-03 are the controls, and the flip-text pattern follows M2-AC20. The sensitivity runs are real (S-WSQ and S-WSQ-guard failed with the intended text). AC6's NEG, AC7a's measured bounds and AC8's `include_deleted` data check assert on data as well as on the UI.

Security: the redaction gates are intact (`upload-gate.ts` is unchanged in this branch, and `playwright.config.ts` changed comments only). `grep -c VALUES` evidence in the plan matches the design. The CI step has no new permissions, no new actions and nothing unpinned.
