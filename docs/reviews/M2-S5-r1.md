## Code findings

1. **minor** `deploy/web/README.md` (Rolling back the web app, and the `:226` upgrade note). The runbook has no note that a tab may need one manual reload after an upgrade, although L22 (ARCHITECTURE §9) and RU-12 ask for it "at the next SE touch". Line 226 mentions it for the upgrade notes only. Scenario: an operator upgrades, the tab hangs on "loading", and the runbook does not say to reload once. Fix: one sentence in the next SE touch (M5-S4 moves this section anyway). Not blocking: the architecture doc carries L22 and the data is safe.
2. **minor** Timeouts (`.github/workflows/e2e.yml:277-289`, `playwright.config.ts`, `tests/e2e/support/timeouts.ts`). Local runs are unbounded or `T=170m`, which fits (M2-S6's 44 tests took 78 min, M2-S5 adds about 30 min, 53 tests). The CI step is 60 min with `globalTimeout` 55 min, `workers` unset, `retries` 1. The new specs use `longSpecTimeoutMs` (25 min) each, but the measured runs were 2 to 5 min each (`H-SWU-01` 2.1 min, `M2-AC16-01` and `-03` 5.0 min; 833 s in total). With CI parallelism the fit is plausible but unproven: no CI duration estimate for the suite after M2-S5 is in the plan. Scenario: the arm64 runner takes more than 55 min and the global timeout cuts the run, with the not-run reporter then flagging the unrun tests. Fix: the proof run decides (below). If over 50 min, the ci-cd-specialist applies the CC-1 route (split a job), and this is not a re-review of M2-S5.
3. **nit** `tests/e2e/support/swTimeline.ts` `userReload`: the `catch {}` after `waitFor` is intentional and commented, and the verdict below it names what is missing. No change needed; noted so it is not read as swallowed error.

Checked and fine:
- **RU-13/RU-15 race branch does not weaken an assertion.** `classifySelfReload` returns `race` only with all four parts: (i) a reload was requested, (ii) the old version went redundant and a different version is activating or activated, (iii) no main-frame commit in 60 s, (iv) no `GET /` in the window. Everything else is `unknown`, which fails the test with the missing parts named. `swu-03/04/05` check that dropping (i), (ii) or (iv) gives `unknown`, and about:blank is not a commit. After a race, `judgeUserReload` still requires a resolved promise, or exactly `net::ERR_ABORTED`, plus a main-frame commit after t0 and a server `GET /`. Any other rejection fails (`swu-09`), a GET without a commit fails and the reverse fails (`swu-08`). Accepting ERR_ABORTED is justified: the user's reload replaces the stuck navigation, and the evidence needed is stronger than Playwright's promise. A small remaining weakness: a commit after t0 could in principle be the stale self-reload rather than the user's reload, but then the page did load the app and a `GET /` was served, and the tests then still assert the new bundle marker, the cached digest, the opened profile and data intact. Not a hole.
- The race branch cannot hide a broken upgrade: the unchanged AC16 assertions (B served, profile opened, local-only edit Y present, snapshots unchanged) follow in both branches.
- No `.only`, no skip, no `waitForTimeout` in the new specs and support files; polling uses `expect.poll`/`waitFor`.
- No upstream code copied: the new support code cites upstream paths in comments only; no file headers or verbatim blocks. No secrets or note content in the diff (my grep for token and password found only runbook prose).
- Docs match the evidence: results in the test plan agree with the RU-15 run log (3 passed, 833 s), the architect's L14/L22/U21 and ADR-0005 amendment and M6-AC8 agree with the plan, and L22's race rates (2/6, 4/6, 2 in 2, 0/7) are quoted as evidence.
