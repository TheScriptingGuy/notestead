## Findings (planning)
- **F1. A Joplin Cloud logo is drawn inside the upstream UI.** `upstream:packages/app-mobile/components/SyncWizard/JoplinCloudIcon.tsx` is an inline `react-native-svg` component (the cloud-and-J mark, blue gradient). The sync wizard shows it on every first start. It is not a file, so no hash check and no static overlay can see or remove it. ADR-0010's context ("no logo images imported into the React UI") holds for image files only; this is the only such component at the pin (`git grep` for `react-native-svg` and image imports in `packages/app-mobile/components`). **This needs the user (Q1 below).** M2-AC11 is read as served icon *files* (Interpretation I1), so F1 does not block this story's tests.
- **F2. Dev mode is observable beyond the flag** (amended by ruling RU-1: at the pin, upstream's production bundle **crashes at start** in dev mode, so only the first and last points below are observable on the NEG side) (upstream at the pin), which gives M2-AC13 a data-level assertion:
  - `upstream:packages/app-mobile/index.web.ts:31-44` sets `window.joplin = { Setting, Note, … }` only `if (__DEV__)`;
  - `upstream:packages/app-mobile/utils/buildStartupTasks.ts:176` sets `Setting` constant `env` from `__DEV__`;
  - `upstream:packages/app-mobile/services/profiles/index.ts:33-41` names the database `joplin-20240127-1.sqlite` in dev and `joplin.sqlite` otherwise. The `opfs` VFS stores it as `/joplin.sqlite.sqlite3` at the OPFS root (WEB-SQLITE-1, M2-S3 WS-3), so dev mode gives `/joplin-20240127-1.sqlite.sqlite3`;
  - `upstream:…/web/public/environment.js:14-16` sets `document.title = 'Joplin DEV'` in dev.
- **F3. The served bundle carries no upstream image file other than `public/`'s.** The six hashed PNGs webpack emits at the bundle root are 36×36 and 63×63 navigation glyphs from `node_modules` (none matches any blob in the upstream tree at the pin), and the bundle's three inline `data:image` URIs are a checkbox tick and canvas code. So the upstream icon set to compare against is `upstream:packages/app-mobile/web/public/icons/*` (6 files) plus `screenshots/*` (2).
- **F4. The image and the bundle can come from different commits.** `source.html` is generated when the *bundle* is built (the artifact's `notestead.commit`). The `web` image adds our `deploy/web/` files (Caddyfile, entrypoint), also AGPL, built from whatever commit builds the image. Locally that is `HEAD` with the `dc515fa` artifact. **Brief for the architect, not a blocker:** state in ADR-0010 which commit the offer names for the image's own files (for example: M5's release builds bundle and image from one commit, the pre-publish gate checks the OCI `org.opencontainers.image.revision` label equals `source.html`'s commit). This plan asserts the bundle's commit (M2-AC12-02).
- **F5. The Caddy site has no SPA fallback** (`deploy/web/Caddyfile`, `file_server` under `root * /srv/www`), so a path the bundle lacks is a 404. The un-overlaid NEGs rely on it (`/source.html` 404).

## Interpretations (for the orchestrator)
- **I1. "Every icon" in M2-AC11** is every icon the bundle serves or declares: the `manifest.json` `icons[]`, `<link rel="icon">`/`apple-touch-icon` and `og:image` of the three pages, and any file under `/icons/`. An icon drawn by upstream React code (F1) is outside the overlay's reach and is handled by Q1.
- **I2. "On the same origin" in M2-AC13's NEG** is read strictly: the overlaid and the un-overlaid bundles are each served in turn on **one** `http://localhost:<P>`, each to a fresh browser context, inside one test. The test asserts both origins are equal.
- **I3. "The un-overlaid bundle"** is reconstructed, not built (D2): the served bundle with every overlay change undone from upstream's `public/` at the pin. It is exactly what `yarn web` produces, because the overlay never touches the webpack outputs (M1-S2 T55 and T90 proved it).
- **I4. "Our exact commit"** is the commit the served bundle was built from: the served artifact's `bundle-manifest.json` `notestead.commit`. It must also be a commit of this repository and an ancestor of `HEAD`.
- **I5. ADR-0010's placement check** ("never covers upstream controls, verified by E2E screenshots on narrow and wide viewports, M2") is verified here by geometry, not screenshots (the harness keeps no screenshots: C1-R1). It has its own test IDs (`M2-S6-ADR10-*`). The planner recommends it gates this story's sign-off, because the ADR assigns it to M2 and this is the overlay story.

## Planner decisions
**D1. Upstream bytes are read at test time and never committed.**
- Upstream's `public/` files at `web.commit` come from git blobs: `JOPLIN_UPSTREAM_DIR`, then `~/joplin-web-app-work/upstream-joplin` if it holds the commit, then a blobless depth-1 fetch cached in `test-results/.cache/upstream/` (gitignored). This is the existing `tests/acceptance/support/upstream.mts` lookup.
- Icon and screenshot hashes are computed in memory. The reconstructed un-overlaid dist (D2) lives under the test's output dir in `test-results/` and is deleted at teardown.
- So no upstream file and no upstream hash list enters the repo (reuse, never fork; trademark rule), and the hashes always match the pin. `check:no-upstream-copy` in WO-7 confirms it.
- The E2E layer reaches that lookup through one TypeScript module (WO-2 decides whether Playwright imports the `.mts` directly or the lookup moves to `tests/support/upstreamTree.ts` with `upstream.mts` re-exporting it). One implementation either way.

**D2. The un-overlaid bundle is reconstructed from the served one, with no build** (worker-scoped fixture `unoverlaidDist`):
1. `podman cp <stack web container>:/srv/www <dir>/served`: the exact served tree.
2. A copy of it without `source.html`, `notestead-overlay.css`, `third-party-notices.txt` and the whole `icons/` directory.
3. Every file of `upstream:packages/app-mobile/web/public/**` at `web.commit` written over it (it restores `environment.js`, `index.html`, `closed.html`, `just-one-client.html`, `manifest.json`, `icons/*`, `screenshots/*`). Modes 0644/0755.
4. **Self-check (`H-UO-01`):** every file not from upstream's `public/` is byte-identical to the served file; every `public/` file equals upstream's blob; `web-build verify --pin upstream/joplin-version.json <dir>` exits non-zero and names all six `icons/*` and `environment.js`.
- **Serving it:** a container of the **image under test**, hardened like `compose.yaml`'s `web`, with `-v <dir>:/srv/www:ro`. Same Caddyfile, headers and entrypoint; only the bytes differ. No product seam is needed (`web-build import` would rightly refuse this bundle).
- Seconds of work instead of the ~43-minute arm64 build; nothing extra to download.

**D3. Extra `web` containers** (`upExtraWeb`, generalising `upWebWithoutHostRewrite`, which stays as a wrapper so M1-AC21's NEG is unchanged):
- `upExtraWeb(state, { label, role, port?, mountDist? })`: on the stack's `front` network, published on `127.0.0.1:<port>`, labelled with the run and the role (`web-extra` or `web-unoverlaid`) so the sweep removes it, ready when `GET /` is 200 (polled, `failFast` on exit).
- Test-scoped fixture `extraWebs`: `start(opts)` and `stop(container)`; teardown removes all and attaches each container's log on failure.

**D4. App contexts on other origins** (test-scoped fixture `appContexts`): `open(baseURL, label)` returns a `WebApp`-shaped object with its own fresh context (OPFS, service worker), `en-GB`, `Europe/Amsterdam`, console capture, the harness's own tracing, and a network recorder. At teardown: the console and trace attached on failure, and the WEB-SQLITE-1 check, exactly as `webApp`'s (move that code into a shared function; `webApp` keeps its behaviour). `close(app)` ends a context early (M2-AC13-01 phase switch).

**D5. Constants are the spec, never read from `overlay.json`** (`tests/support/branding.ts`): product name `Notestead for Joplin (unofficial)`, short name `Notestead`, notice `Not affiliated with or endorsed by JOPLIN SAS` (matched case-insensitively on "not affiliated" and "JOPLIN SAS"), our repository `https://github.com/TheScriptingGuy/notestead` (or `NOTESTEAD_SOURCE_REPO` when set, the production override). Reading expectations from `overlay.json` would make the tests tautological.

**D6. The oracles for "from our overlay" and "our commit"** come from the served artifact: `NOTESTEAD_WEB_ARTIFACT/bundle-manifest.json` gives `notestead.commit` = C. Our icons are `git show C:packages/web-build/overlay/icons/<name>` in this repository. If `NOTESTEAD_WEB_ARTIFACT` is unset, the M2-AC11-01 and M2-AC12-02 tests **fail** with an instruction (never skip). CI's `e2e.yml` sets it (lines 279, 291) and checks out with `fetch-depth: 0`.

**D7. The served-file scan (M2-AC11-02).** The set scanned is the union of:
- every regular file in the served tree (D2 step 1), as a URL path;
- every same-origin URL the browser requested while loading `index.html` to the sync wizard, `closed.html`, `just-one-client.html?no-retry=1` and `source.html` (network recorder);
- probes for upstream's names: every `public/` path at the pin (for example `/icons/icon-large.png`, `/screenshots/tall.png`), plus `/favicon.ico` and `/apple-touch-icon.png`.

Each is fetched **through the web container** with Node (no `Accept-Encoding`), and its body hashed whatever the status. The assertions:
- no body's sha256 is an upstream icon hash (the AC);
- no body's sha256 is an upstream screenshot hash (ADR-0010 "screenshots removed"; reported separately);
- the scan is not vacuous: it fetched at least as many paths as the served tree has files, and at least one PNG.

**D8. The placement criterion (ADR-0010, `M2-S6-ADR10-*`).** A control is **covered** if either:
- `elementFromPoint` at the centre of the control's visible box is the Source link or inside it; or
- the intersection of the two boxes is at least 25% of the control's box area.

"Controls" are visible elements with role `button`, `link`, `checkbox`, `switch`, `menuitem`, `tab`, `combobox` or `radio`, in every frame (box in page coordinates), the Source link excluded. Textboxes and editors are not controls here: their overlap is recorded as an annotation only. The pure function `coveredControls(controls, linkBox)` is unit-tested.

**D9. L20 (the tie, user decision 2026-11-13; ARCHITECTURE §9).** The E2E tests start the web app (M2-AC13-01 twice). The M2-S4 D12 rule applies unchanged:
- a qualifying failure (only `rc= -1`/`rc= 10`; shape A, B or WS-1-only; `web-sqlite.json` attached; nothing else failing in that test) is an **L20 occurrence**, recorded with the test, `rc`, statement kind, database, whether startup failed, and the evidence path (`node tests/harness/tools/scan-l20.ts test-results/e2e`);
- it is **never re-run to get green**;
- the third occurrence in one run (one local Playwright invocation; one arm64 runner's E2E step in CI) is a **HARD STOP**; on x64, CI counts and never blocks.

The M2-AC13-01 NEG phase runs upstream's dev mode. A SQLite failure there is still recorded, but counts as an occurrence only if it qualifies.

**D10. Bounds.** App start: `appStartTimeoutMs` (3 min) per phase. Extra container ready: 60 s. OPFS reads: 30 s (`waitFor`). The keyboard walk: at most 200 Tab presses, each followed by a focus read (no sleeps). Specs use `longSpecTimeoutMs`.
