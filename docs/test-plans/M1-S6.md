# F1 (fixed-sleep lint ban): one lint run with the fixtures in place (~1.5 min)
node --test --test-concurrency=1 --test-reporter=spec 'tests/acceptance/m1-s6/*.test.mts'

# unit tests of the harness's redaction and zip code (part of `corepack yarn test`)

# developer use of the stack (reuse mode, M1-AC19 positive path)

**Healthchecks** (every service, in the compose files, ADR-0006 amendment 2026-10-05):
- `server`: `GET /api/ping` on `127.0.0.1:22300` with the Host of `APP_BASE_URL` (any other Host gets `Invalid origin`), body `{"status":"ok"}`; `start_period` 180 s.
- `web`: `wget -q -O /dev/null http://127.0.0.1:8080/` (`deploy/web/README.md`).
- `headless`: `GET http://127.0.0.1:8090/healthz` → 200 (M1-AC15: only after the initial sync and decryption); `start_period` 600 s.

**Lifecycle** (`tests/stack/stack.ts`): `newStack()` runs the guard first, then names everything (`nst-<name>-<run>`, labels `io.github.thescriptingguy.notestead.test=stack`, `…test-run=<run>`, `…stack-role=<service>`); `upCore()` runs `podman compose up -d server web` and polls each container's health: `healthy` for all → done; `unhealthy`, exited or no healthcheck → abort at once with `stack service "<name>" (container …) is <state>; healthcheck: …; last check output: …`; `createAccount()` (admin API, strong unique password), `enableE2ee()` (the M1-S5 "other device", through `web:8080`), `upHeadless()` (compose project `<stack>-hl-<label>`, healthy), `downStack()` (logs written redacted, `compose down -v` per project, labels swept, work dir and built images removed).

**podman-compose 1.3.0 facts the harness works around** (checked in its source, `/usr/lib/python3/dist-packages/podman_compose.py`):
- `up -d` starts every container with `podman run -d` *before* waiting for `depends_on` conditions, and waits for `service_healthy` with `podman wait`, which never returns for a service that stays unhealthy. The harness therefore polls health itself and aborts on `unhealthy`.
- Lists are appended when override files are merged, so healthcheck `test` values are strings (CMD-SHELL), which replace.
- Projects run in a pod by default (shared network namespace: `web` would reach `headless`'s `127.0.0.1:41184`). Both files set `x-podman: {in_pod: false}`; `docker compose` ignores `x-` keys.
- Podman healthchecks run from systemd timers (verified on the Pi: a 1 s check turns `healthy` in ~1 s). CI (M1-S8) must confirm the same on the GitHub runners, or set `NOTESTEAD_COMPOSE='docker compose'`.

## Playwright harness
- **`playwright.config.ts`** (written now, before implementation, process rule P1): `testDir: tests/e2e`, `**/*.spec.ts`; 1 worker locally; retries 0 locally, 1 in CI; `trace: 'retain-on-failure'`; `globalSetup: tests/e2e/support/globalSetup.ts`; reporters: the redacting reporter **first**, then `list`, `html` (`playwright-report/`) and `junit` (`test-results/e2e/junit.xml`).
- **globalSetup:** the guard (M1-AC19), then the whole stack (server, web, a default E2EE account and its headless service) up and healthy **before any test runs** (M1-AC18), or the run aborts with `Notestead test harness: aborting before any test runs.` and the cause; its teardown removes everything. The stack state reaches the workers in `NOTESTEAD_E2E_STACK`.
- **Fixtures** (`tests/e2e/support/fixtures.ts`): worker `stack`, `joplinServer` (`url`, `proxiedUrl`, `publicUrl`, `request`); test `e2eeAccount`, `headlessService`, `dataApi`, `webApp` (fresh `BrowserContext` on `http://127.0.0.1:<web port>`; console and page errors recorded), and the automatic `stackLogs`.
- **Attachments on failure:** `server.log`, `web.log`, `supervisor-default.log` (the test's time span, `podman logs --since`), `supervisor.log` (the test's own headless service, before it is removed), `browser-console.log`, and Playwright's `trace`. Every one is redacted when written; the **redacting reporter** then redacts every attachment file in place (the trace zip entry by entry: `{name, value}` header pairs, `token=` in URLs, console texts) before the HTML/JSON/JUnit reporters copy anything (they copy at `onEnd`). An attachment that cannot be redacted is deleted.
- **Page objects** (`getByRole`) arrive with M1-S7, which is the first story that drives the real app; the M1-S6 bundle is the F3 fixture.
- **Chromium (F2).** Playwright 1.59.1 expects `chromium-1217`; the Pi has `chromium-1223` (Chromium 148.0.7778.0). `tests/e2e/support/chromium.ts` uses Playwright's own revision when installed, otherwise the newest installed `chromium-<rev>` as `executablePath` (spike S4 proved r1223 works), `NOTESTEAD_CHROMIUM=<path>` to override; in CI, Playwright's own browser. **No download is needed on the Pi**, and the harness never downloads one. Residual: the Pi tests Chromium 148, CI tests 147; a difference would show as an arm64-only failure, which CI's arm64 job (M1-S8, Playwright's own browser) separates from architecture.

## Harness self-tests
The ACs are about the harness's behaviour in a real run, so each self-test runs the harness the way a user does: an **inner** Playwright process (`corepack yarn playwright test -c tests/harness/playwright.selftest.config.ts selftest/<spec>`, same globalSetup, fixtures and reporters, plus a JSON report) started by an **outer** Jest contract test that checks the exit code, the console output, the JSON report, the files written and podman's state before and after. The inner specs (`tests/harness/selftest/*.spec.ts`) are never part of a normal run (the main `testDir` is `tests/e2e`; the self-test config refuses to load without `NST_SELFTEST_OUT`), because one of them fails on purpose.

## Interpretations (for the architect / orchestrator)
1. **The stack is started once per Playwright run in globalSetup**, not per worker as ADR-0007 sketches: "healthy before any test starts" then holds literally, and an unhealthy service aborts the run before any test (M1-AC18 NEG). Isolation is unchanged: a fresh user per test (`e2eeAccount`), a fresh headless compose project and profile volume per test (`headlessService`), a fresh BrowserContext per test (`webApp`). `clearDatabase` is not needed because the whole stack is thrown away at the end of each run.
2. **The `headless` fixture is called `headlessService`.** Playwright reserves `headless` for its own browser option; using it as a fixture name breaks the fixture types.
3. **"a container it started" (M1-AC19)** = a running container with the stack labels whose published `22300` port is the URL's port on `127.0.0.1`. Such a URL attaches the run to that stack (reuse mode, `cli.ts up`), which the run never tears down. Only `http://127.0.0.1|localhost:<port>` without credentials, path or query can match.
4. **"No request is made" (M1-AC19 NEG)** is proven with a local canary listener rather than with `example.com` (no way to observe a request that did not reach a third-party host). The guard itself only calls `podman ps`/`podman port`.
5. **M1-AC18 "without leaving containers, pods or networks behind"** also covers volumes.
6. **M1-AC20 "Playwright trace"** is Playwright's own retain-on-failure trace of the test's contexts, redacted by the reporter; the `web` log is attached too (the 502 path needs it).
7. **M1-AC34 trailing slash:** the review offered two fixes (normalise, or refuse with 64); the test accepts either and rejects what happens today (Caddy's own exit 1).
8. **M1-AC34 "leaves no Caddy process listening"** is proven by the container having exited with 64, no Caddy log line and no entrypoint banner: Caddy logs before it listens, and the entrypoint `exec`s Caddy only after all checks.

## Requirements on the implementation
- **R1 (F1, `eslint.config.js`):** extend the "No fixed sleeps in tests (ADR-0007)" block.
  - **Files:** `tests/**` and co-located `**/*.test.{ts,mts}`, `**/*.spec.ts`.
  - **Banned:** `page.waitForTimeout` (kept); any call of the global `setTimeout(…)` (`CallExpression[callee.name="setTimeout"]`, which covers `new Promise(r => setTimeout(r, n))` and callback delays); `globalThis.setTimeout`/`window.setTimeout`/`global.setTimeout`; importing `setTimeout` (under any alias) from `timers/promises` or `node:timers/promises`. Any restriction rule is fine (`no-restricted-syntax`, `no-restricted-imports`, …). The message points to `waitFor` (`tests/support/poll.ts`) and `expect.poll`.
  - **Allowed:** member calls such as `req.setTimeout(ms, cb)` (socket deadlines), `AbortSignal.timeout`, Jest fake timers.
  - **Exempt files, exactly:** `tests/support/poll.ts` (the one polling primitive; QA moved `waitFor` there from `tests/contract/support/podman.ts`) and `tests/fixtures/**/*.mjs` (programs that run inside containers and sample at an interval: `health-watch.mjs`, `proc-watch.mjs`).
  - Also apply the Playwright rules (`no-focused-test`, `no-skipped-test`) to `tests/**/*.spec.ts`, so the harness self-tests (`tests/harness/selftest/`) are covered.
- **R2 (F3, `packages/headless`):** when `process.pid === 1`, the supervisor writes **one** line at startup that contains `PID 1` and `init` (suggested: `warning: running as PID 1 without an init; start the container with --init (compose: init: true) so that stopped CLI children are reaped`), and carries on; no such line otherwise. Unit-test it next to the code.
- **R3 (M1-AC34, `deploy/web/notestead-web-entrypoint.sh`):** a `JOPLIN_SERVER_URL` ending in `/` must either be normalised (strip trailing slashes, as for `JOPLIN_SERVER_PUBLIC_URL`) or refused with exit 64 naming the variable; it must never reach Caddy. Everything else in M1-AC34 already holds and must keep holding.
- **R4 (F4, `packages/headless/README.md:14`):** describe the install order as the Containerfile does it: a focused production install from `yarn.lock`, then a lockfile check that fails the build when `yarn.lock` does not match the manifests. Checked by the lead, not by a test.

## Harness validation (before RED, 2026-10-09, Pi arm64)
Everything below ran on the Pi (podman 5.4.2, podman-compose 1.3.0, Node 24, Playwright 1.59.1 with `chromium-1223`). Logs are under `test-results/verify/m1-s6/` (gitignored).
- **Stack bring-up** (`node tests/stack/cli.ts up`, cold image builds): web image 16 s (F3, cached upstream files), headless 212 s, device ~2 min; then server and web healthy, the E2EE device seeded, the default headless healthy (~35 s after its start). `podman inspect`: no pod, `HostConfig.Init` true on headless only, web publishes only `8080`, headless on `back` only. `cli.ts down`: `podman ps -a`, `network ls`, `volume ls`, `pod ls` back to the user's `byparr` set (`qa-cli-up-1.log`).
- **Reuse mode:** `selftest/guard.spec.ts` with `JOPLIN_SERVER_URL` set to that stack's server passed (attached, pinged the server); with `https://example.com` it aborted in globalSetup with the guard's message.
- **M1-AC20 against the same stack:** every attachment present; the outer checks (run as a script against the output) found **0 leaks** over 26 text views, every positive control present.
- **Sensitivity (M1-AC20):** the same inner run with the redacting reporter removed (a temporary config, deleted afterwards) gives **70 leaks**, among them the planted in-page secret in the trace's `0-trace.trace` (console) and `0-trace.network` (URL and header), and the test source and `error-context.md` (`?token=`, `X-API-AUTH: …`).
