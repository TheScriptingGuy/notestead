# Test plan: M1-S2 Web bundle build and overlay (scripts)

- **Story:** `docs/backlog/M1.md` § M1-S2 (M1-AC5, M1-AC6, M1-AC7 and their NEGs). **ADRs:** 0001, 0010 (0007 for test rules).
- **Branch:** `feat/M1-S2-web-build`. **Owner of this plan:** qa-specialist.
- **Runner:** Node `node:test` acceptance suite (`tests/acceptance/m1-s2/`), black-box through `corepack yarn workspace web-build …`, as in M1-S1 (`docs/testing/strategy.md` §3). The AC labels "unit" for AC6/AC7 mean *small fixtures, no containers*; the tests still call the real commands so they hold whatever the internal module layout is. The engineer's own Jest unit tests in `packages/web-build/src/**` are expected as usual (M1-AC1) and are not a substitute for these. `corepack yarn test` (Jest) is unchanged and stays fast; no runner config (Jest, Playwright, tsconfig) needed changes: the existing acceptance glob and `tests/acceptance/tsconfig.json` already cover the new files.

## How to run
```sh
# default suite: AC6, AC7, AC5 packaging seam, harness self-checks (~35 s on the Pi; needs the upstream tree, see Fixtures)
node --test --test-concurrency=1 --test-reporter=spec 'tests/acceptance/m1-s2/*.test.mts'

# opt-in, local only: overlay → verify → package on a real built bundle (~10 s; default: the spike S1 dist)
NOTESTEAD_REAL_DIST=~/joplin-web-app-work/spikes/S1/joplin/packages/app-mobile/web/dist \
  node --test --test-reporter=spec tests/acceptance/m1-s2/optin/ac5-real-dist.optin.mts

# opt-in, heavy: the full M1-AC5 build (CI x64; ~43 min and ~7 GiB peak on the Pi, so it needs an explicit interlock there)
NOTESTEAD_ALLOW_ARM64_WEB_BUILD=1 NOTESTEAD_BUILD_WORK=<new or empty dir, or one from an earlier build; ~15 GB free> \
  node --test --test-reporter=spec tests/acceptance/m1-s2/optin/ac5-build.optin.mts
```
- `NOTESTEAD_BUILD_WORK` (optional, default: a temp dir) must be a **new or empty** directory, or one created by an earlier `build` (it carries the marker file `.notestead-web-build-work`). `build` refuses any other directory and names it, without changing anything in it. It resets and cleans a marked directory before building, so never point it at a checkout you care about. (Amended in M1-S3, after review M1-S2-r3.)
- `NOTESTEAD_BUILD_OUT` (optional, default: a temp dir deleted after the run) must be a new or empty directory. T90 leaves the artifact it verified there, so `web-bundle.yml` uploads exactly that artifact (M1-AC27: same `SHA256SUMS`, no second build). (Added in M1-S3.)
- `*.optin.mts` files do not match the default `*.test.mts` glob, so nothing is skipped: they are separate suites that run only when named.
- Every command's output, exit code and duration is logged to `test-results/acceptance/m1-s2/<label>.log` (gitignored, redacted).
- Optional: `JOPLIN_UPSTREAM_DIR=<clone containing web.commit>` avoids the network (it is also passed to `verify --upstream`).

## Command contracts (binding for the implementation)
All commands run as `corepack yarn workspace web-build <script> …`, so `packages/web-build/package.json` defines the scripts `overlay`, `verify`, `package` and `build`. Yarn runs workspace scripts with the workspace as cwd, so the tests always pass **absolute** paths. Options may come before or after the positional `<dist>`. Exit 0 on success, non-zero on any failure. Every failure message names the offending path.

| Command | Contract |
|---|---|
| `overlay <dist> [--pin <file>]` | Applies `packages/web-build/overlay.json` to `<dist>` **in place**. If any must-exist target (below) is missing it exits non-zero and names it (for example `environment.js`); checking all targets before changing anything is recommended but not tested. Results: `environment.js` sets `window.__DEV__ = false` unconditionally and keeps the `window.exports = {}` and `window.process.env.EXPO_OS = 'web'` shims, and nothing else (it does not touch `document.title`). `manifest.json` has `name` = `Notestead for Joplin (unofficial)`, `short_name` = `Notestead`, keeps `start_url: "./"` and `display: "standalone"`, has no `screenshots` key, and lists our icons: PNG 64x64, 192x192, 256x256 and 512x512 plus one `image/svg+xml`, each `src` `./…` pointing at a file that exists in the overlaid dist. `screenshots/` is removed. `source.html` is generated. `index.html` keeps its CSP `<meta>` and its `<script>` tags byte-identical. The webpack outputs (`*.bundle.js`, `*.wasm`, fonts, `pluginAssets/**`) are not modified. Every `./…` reference in `index.html`, `closed.html`, `just-one-client.html` and `source.html` resolves to a file in the overlaid dist. `source.html` contains the upstream commit (`web.commit`), the upstream repo URL (`web.repo` without `.git`), at least one `href` containing `web.commit`, our commit (`git rev-parse HEAD` of this repo) and the text `AGPL-3.0`. |
| `verify [--upstream <git-dir>] [--pin <file>] <dist>` | Hashes every regular file under `<dist>` (recursively, any name, any depth) and fails if any file's sha256 equals that of a file in `upstream:packages/app-mobile/web/public/icons/*` at the pin's `web.commit`. Names every offending file by its path relative to `<dist>` (POSIX separators). A missing `<dist>` fails and names it. Without `--upstream` it obtains the icon hashes itself (for example the cached blobless fetch that `check:no-upstream-copy` already implements, `packages/web-build/src/upstreamCopy.ts`), so CI and the Pi use the same code path. A committed hash list is acceptable only if it is checked against `web.commit`; the tests derive the hashes independently, so a stale list fails them. `verify` may check more (ADR-0010 also names `__DEV__` and the CSP), as long as an overlaid bundle passes. |
| `package <dist> --out <dir> [--pin <file>]` | **Test seam** for the packaging step of `build` (see Interpretation 2). Packages `<dist>` as it is (no overlay, no verify) and writes exactly three files into `<dir>` (created if missing): `web-bundle-<web.tag>.tar.zst`, `SHA256SUMS` and `bundle-manifest.json` (format below). A missing `<dist>` fails, names it and writes no tarball. `--pin` selects the pin file (default `upstream/joplin-version.json`). |
| `build --out <dir> [--work <dir>] [--pin <file>]` | M1-AC5. Clones (or fetches) `web.repo` at exactly `web.commit` into `--work` (default: a cache or temp dir of the engineer's choice), runs the upstream recipe unmodified: `corepack yarn install` with `SKIP_ONENOTE_CONVERTER_BUILD=1`, then `cd packages/app-mobile && yarn web`. It then runs `overlay`, `verify` and `package` on `packages/app-mobile/web/dist` and writes the same three files into `--out`. It echoes each recipe command with its environment overrides (the test looks for `SKIP_ONENOTE_CONVERTER_BUILD=1` and `yarn web`). |

### `overlay.json` (location and schema)
- Location: `packages/web-build/overlay.json`.
- Shape: `{ "rules": [ { "path": "<dist-relative POSIX path>", "action": "<name>", …action-specific fields } ] }`.
- The tests rely on two things only:
  - Every rule has a non-empty string `path` and `action`.
  - `action: "generate"` creates a new file. **Every other action requires `path` to exist** in `<dist>`; a missing one fails the overlay and is named.
- Required coverage (from the ADR-0010 table): must-exist rules for `environment.js`, `manifest.json`, `index.html`, `just-one-client.html`, `closed.html`, `icons` (the directory or files under `icons/`) and `screenshots` (the same), and a `generate` rule for `source.html`. More rules (for example `third-party-notices.txt`) are fine.
- Suggested, not tested: `replace` (with a `source` path relative to `packages/web-build/`), `replaceDir`, `remove`, `editJson` (`set`/`delete`), `editHtml`. Our replacement assets live under `packages/web-build/overlay/`.

### Artifact format (`build` and `package`)
- `web-bundle-<web.tag>.tar.zst`: a zstd-compressed tar (`tar --zstd -xf` works with GNU tar). Entries are relative to the bundle root (`index.html` at the top, a leading `./` is fine). There are no absolute paths, no `..` segments, and only regular files and directories (no symlinks or devices). It contains exactly the files of the packaged dist, byte for byte.
- `SHA256SUMS`: `sha256sum` format (`<64 hex><space><space or *><name>`), with one line each for the tarball and `bundle-manifest.json`. `sha256sum -c SHA256SUMS` passes in the output dir.
- `bundle-manifest.json`:
  ```json
  {
    "upstream": { "repo": "<web.repo>", "tag": "<web.tag>", "commit": "<web.commit>" },
    "notestead": { "commit": "<git rev-parse HEAD, 40 hex>" },
    "files": [ { "path": "index.html", "sha256": "<64 hex>", "size": 1670 } ]
  }
  ```
  `files` lists every file in the tarball and nothing else, sorted by `path` (plain JS string comparison). Extra top-level fields (for example a dirty-tree flag) are allowed.

## Fixtures
- **F1, synthetic dist** (`syntheticBundle()` in `tests/acceptance/support/webBundle.mts`). It is generated by code into a temp dir. It is not a committed directory, because `.gitignore` ignores `dist/` and eslint would lint its browser JavaScript. It has the upstream layout with our own content:
  - `index.html` with a multi-line, tab-indented CSP `<meta>`, manifest and icon links, and three script tags
  - a dev-mode `environment.js`
  - `manifest.json` with icons and screenshots
  - `icons/*`, `screenshots/*`, `closed.html`, `just-one-client.html` and the CSS files
  - stand-ins for the webpack outputs (`app.bundle.js`, `serviceWorker.bundle.js`, a chunk, a `.wasm`, a `.ttf`, `pluginAssets/katex/katex.css`, a `LICENSE.txt`)

  It needs no network. H4 proves it contains no upstream bytes.
- **F2, the un-overlaid upstream static files.** These are `upstream:packages/app-mobile/web/public/**` at `web.commit` (exactly what `yarn web` copies into `dist/`), plus F1's webpack stand-ins. They are generated at test time and **never committed**.
  - Source, in order: `JOPLIN_UPSTREAM_DIR`, then `~/joplin-web-app-work/upstream-joplin` if it contains `web.commit`, then a blobless depth-1 fetch of `web.repo` at `web.commit` cached in `test-results/.cache/upstream/`. Blobs are fetched lazily, about 3.5 MB.
  - F2 is "the upstream" of M1-AC6's CSP check and the "un-overlaid fixture" of the M1-AC7 NEG.
- **Upstream icon hashes** (M1-AC7) are derived at test time from F2's `icons/*`: six files at the pin.
- **Real dist (opt-in only).** This is an upstream `yarn web` output, by default the spike S1 build (22 MB). The test copies it to a temp dir, and it is never committed.

## Interpretations and findings (for the architect / orchestrator)
1. **The artifact is overlaid.** The story goal says `web-build` "builds the pinned upstream bundle, applies the overlay and packages an architecture-neutral artifact", and M5 forbids upstream icon hashes in any artifact. So T90 requires the `build` output to pass `verify` and carry our `manifest.json`/`environment.js`/`source.html`. M1-AC5's three numbered steps don't mention the overlay; if the architect intends a raw upstream artifact with the overlay applied in the `web` image (M1-S4), T90's overlay assertions move to M1-S4 and this plan is amended.
2. **The `package` seam.** M1-AC5 can only be fully exercised by the 43-minute build. To test the artifact format on every run (both architectures, seconds), this plan adds `package <dist> --out <dir>` as a production seam. `build` must use the same code path for its final step. The AC wording ("produces … `tar.zst` plus `SHA256SUMS` plus `bundle-manifest.json`") specifies the outputs, not the command structure, so the seam doesn't contradict it.
3. **"The CSP `<meta>` is byte-identical to upstream"** is read as: the exact source text of the CSP `<meta>` element, from `<meta` through its closing `>` and including inner whitespace and line breaks, is unchanged, and it is the only CSP `<meta>`. On F2 the input *is* upstream's `index.html` at `web.commit`. T55 also requires the `<script>` tags to be unchanged and in the same order, as ADR-0010 states ("The upstream CSP and script tags stay byte-identical").
4. **"Our name" is the ADR-0010 amendment's**: `Notestead for Joplin (unofficial)` / `Notestead`. ADR-0010 lists our icons as SVG + PNG 64/192/256/512; T52 checks exactly those sizes in `manifest.json`.
5. **The opt-in mechanism.** CLAUDE.md forbids skipped tests. The full build is not a conditionally skipped test: it lives in a file the default glob never matches and runs only when named (CI x64 in M1-S3's `web-bundle.yml`; the Pi on request). The arm64 interlock *fails* with instructions instead of skipping.
6. **ADR-0010's other verify checks** (`__DEV__` false, CSP unchanged) are not in M1-AC7's text, so they are not required of `verify` here. They are asserted directly on the overlay output (T51, T55) and in T90/T95. M2-AC11/M2-AC13 cover them end to end.
