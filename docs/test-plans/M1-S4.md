- **Story:** `docs/backlog/M1.md` § M1-S4: M1-AC10, M1-AC11, M1-AC12, M1-AC13, M1-AC28 and their NEGs, with the gate 1 amendments (Cloudflare Tunnel front, spike S6). **ADRs:** 0002 (proxy rules 1–8), 0006 (topology, ports, hardening, cache headers), 0008 (web origin headers, log redaction); 0007 for the test rules.
- **Branch:** `feat/M1-S4-web-container`. **Owner of this plan:** qa-specialist. **Implementer:** senior-engineer.
- **Runners:**
  - **M1-AC28 (integration):** the `node:test` acceptance suite (`tests/acceptance/m1-s4/`), black-box through `corepack yarn workspace web-build import …`, as in M1-S2 and M1-S9.
  - **M1-AC10–13 and the image half of M1-AC28 (contract):** Jest with a new config, `jest.contract.config.js` (ADR-0007: contract = Jest + podman). It runs real containers under podman: the image under test, a throwaway `joplin/server:<pin>`, and Node fixture containers. `corepack yarn test` is unchanged and stays container-free.

## How to run
```sh
# M1-AC28 import (seconds; needs the upstream tree like M1-S2: local clone, JOPLIN_UPSTREAM_DIR or the cached fetch)
node --test --test-concurrency=1 --test-reporter=spec 'tests/acceptance/m1-s4/*.test.mts'

# contract suite (podman; one heavy job at a time; ~3–5 min on the Pi once the image exists)
corepack yarn jest -c jest.contract.config.js tests/contract/m1-s4

# Pi, real bundle (opt-in): package the spike S1 dist, import it, keep the artifact, then run the contract suite on it
NOTESTEAD_ARTIFACT_OUT=$HOME/joplin-web-app-work/m1-s4/artifact \
  node --test --test-reporter=spec tests/acceptance/m1-s4/optin/ac28-real-dist.optin.mts
NOTESTEAD_WEB_ARTIFACT=$HOME/joplin-web-app-work/m1-s4/artifact corepack yarn jest -c jest.contract.config.js tests/contract/m1-s4
```
- The opt-in file does not match the default `*.test.mts` glob. It is a separate suite run by name, not a skipped test (strategy §3).
- Logs:
  - `test-results/acceptance/m1-s4/<label>.log`: every `web-build` command of AC28.
  - `test-results/acceptance/m1-s4-image/*.log`: the image preparation (package, import, `podman build`).
  - `test-results/contract/m1-s4/<suite>/<container>.log`: every container's log, written at teardown and redacted (`token=`, `X-API-AUTH`). The web container's log is its Caddy access log.
  - `test-results/contract/m1-s4/ratelimit/Caddyfile.*`: the R3-neg variant and its source.
- `NOTESTEAD_KEEP_IMAGE=1` keeps `localhost/notestead-web:m1-s4-test` after the run. By default `globalTeardown` removes it.
- Optional root convenience script (engineer, never part of `test`): `"test:contract": "jest -c jest.contract.config.js"`.

## Command contracts (binding for the implementation)
Same conventions as M1-S2: `corepack yarn workspace web-build <script> …`, absolute paths, exit 0 on success, non-zero on any failure, and every failure names the offending path or field.

| Command | Contract |
|---|---|
| `import <artifact-dir> --out <dist> [--pin <file>] [--upstream <git-dir>]` | M1-AC28. `<artifact-dir>` holds the three files that `package`/`build` write (M1-S2 §Artifact format): `web-bundle-<web.tag>.tar.zst`, `SHA256SUMS` and `bundle-manifest.json`. `--pin` defaults to `upstream/joplin-version.json`. `--upstream` is passed to the verify step, as for `verify`. **`--out` must be absent or an empty dir.** Otherwise import fails, names it and changes nothing in it. |
| | **Before extracting anything:** (1) `SHA256SUMS` has a correct line for the tarball **and** for `bundle-manifest.json`. A missing line fails (fail closed). (2) `bundle-manifest.json` `upstream.repo`, `upstream.tag` and `upstream.commit` equal the pin's `web.repo`, `web.tag` and `web.commit`. (3) Every tar member is a regular file or a directory. Symlinks, hard links, devices and FIFOs fail. Its path is relative (no leading `/`) with no `..` segment, and every regular-file member is listed in `files`. A leading `./` is fine. Directory members need not be listed. POSIX/pax extended headers (as GNU tar writes them for `package`) are metadata, not members. |
| | **After extracting:** every `files` entry exists, with the listed sha256 (and size); nothing outside `files` exists; `verify` passes on the result (same code path as the `verify` command). |
| | **On any failure:** non-zero exit, a message naming the reason (the file and `SHA256SUMS`; the field `upstream.commit`/`.repo`/`.tag` and the artifact's value; the tar member's name; the mismatching file; verify's findings), and `--out` **absent or empty** afterwards. Nothing is written outside `--out`. Extracting into a staging dir and renaming on success is one way to do this; it is not required. |

## Image contract (binding for the implementation)
The contract tests build and run the image exactly like this. Nothing else is assumed.

- **Build.** `podman build -f deploy/web/Containerfile --build-context dist=<dist> -t localhost/notestead-web:m1-s4-test deploy/web`.
  - The build context is `deploy/web`. The bundle comes from the **named build context `dist`** (`COPY --from=dist …`), so a local `dist/` and an imported one take the same path (M1-AC28). podman 5.4 and docker buildx both support `--build-context`.
  - `<dist>` is always the output of `web-build import`.
- **Run** (ADR-0006 hardening): `podman run -d --network <test net> --ip <fixed> -p 127.0.0.1::8080 -p 127.0.0.1::8089 --read-only --tmpfs /tmp --cap-drop=ALL --security-opt no-new-privileges --memory 128m -e … localhost/notestead-web:m1-s4-test`.
  - There is no `--user`, no command override and no volume. The image's own `USER` must be non-root, and the image must start and serve under exactly these flags.
  - Ready means `GET :8080/` returns 200.
- **Ports.** `:8080` is public: the bundle at `/`, the proxy under `/joplin-server/*`. `:8089` is internal: only `/joplin-server/api/*`, everything else 404.
- **Environment** (ADR-0002 §Configuration):

  | Variable | Required | Meaning in the tests |
  |---|---|---|
  | `JOPLIN_SERVER_URL` | yes | the address Caddy dials, for example `http://10.89.N.30:22300` (the test server or the echo upstream) |
  | `JOPLIN_SERVER_PUBLIC_URL` | yes | the server's `APP_BASE_URL`: `https://joplin.example.test`; the target of the `/shares/<id>` redirect |
  | `JOPLIN_SERVER_HOST` | no | Host override. **Unset in the main stacks**, so the default (the host of `JOPLIN_SERVER_PUBLIC_URL`, `joplin.example.test`) is under test. C1-neg sets it to `notes.example.test`. |
  | `COEP` | no | default `credentialless`; the tests also run `require-corp` |
  | `TRUSTED_PROXIES` | no | default: none trusted. Tunnel mode sets `<cloudflared stand-in>/32`, a single fixed address on the test network. |
  | `CLIENT_IP_HEADER` | no | tunnel mode: `CF-Connecting-IP`; used only for peers in `TRUSTED_PROXIES` |
- **Caddy config at `/etc/caddy/Caddyfile`.** The R3-neg variant is the image's own `/etc/caddy/Caddyfile` (copied out with `podman create` + `podman cp`) with every line matching `^\s*header_up\s+X-Real-IP\b` removed and nothing else changed. It is mounted read-only over the same path. So:
  - the X-Real-IP overwrite must be such a line (or lines) in that file;
  - Caddy must read that file at start (env placeholders such as `{$VAR}` are fine);
  - an entrypoint that computes the `JOPLIN_SERVER_HOST` default must still run Caddy on that file, not on a copy generated elsewhere.
- **Logs.** The access log of both listeners goes to the container's stdout/stderr (`podman logs`), with the redaction of ADR-0002 rule 7.
- **Pitfall found while validating the harness:** Caddy's `encode` skips a response that already carries `Cache-Control: no-transform`. If the header is set before `encode` sees the response, `ac12-s6` fails, because the bundle is never compressed. A `header` with `defer` ahead of `encode`, or precompressed sidecars, avoids this. This is a hint, not a requirement.

## Fixtures
- **F3, servable bundle** (`servableInputTree()`/`overlaidServable()` in `tests/acceptance/support/webImport.mts`). It is M1-S2's F2 (upstream `packages/app-mobile/web/public/**` at `web.commit`, generated at test time, never committed, plus the synthetic webpack outputs) with:
  - a placeholder `third-party-notices.txt`
  - a **64 KiB compressible `app.bundle.js`** (our bytes; above Caddy's 512-byte `encode` minimum)

  It is then overlaid by the real `overlay` command, so it passes `verify`. `package` turns it into the default artifact for both suites.
- **Hand-written artifacts** (`ustar()`/`writeHandmadeArtifact()`). A ~60-line ustar writer produces the hostile members exactly as specified: symlink, `../…`, absolute path, unlisted member placed **last** (so a streaming extractor that stops midway leaves files behind). Each variant has a manifest and a `SHA256SUMS` that are consistent, so only the property under test is wrong. I00 proves GNU tar reads them with the intended names and types. I02 proves an honest hand-written artifact imports.
- **Real bundle (opt-in, Pi only):** the spike S1 `yarn web` output. It is overlaid and packaged locally (I90), then used through `NOTESTEAD_WEB_ARTIFACT`. It is never committed, and the 43-minute build is never run. In CI the same variable will point at the `web-bundle.yml` artifact (M1-S8).
- **Contract stacks:** one podman network per suite, with a free fixed `/24` (`10.89.200–254.0/24`, chosen at run time to avoid existing networks) and fixed addresses:
  - `.10`: the cloudflared stand-in (a Node client container)
  - `.11`: an untrusted peer
  - `.20`–`.22`: web containers
  - `.30`: `joplin/server:<pin.server.tag>` (`node dist/index.js --env dev --env-file /dev/null`, `APP_BASE_URL=https://joplin.example.test`, `JOPLIN_IS_TESTING=1` except in the rate-limit suite). Readiness is polling `GET /api/ping` for `{"status":"ok"}`, never a sleep. It is seeded with `createTestUsers`.
  - `.40`: the echo upstream
  - `.50`–`.52`: LAN clients

  Fixture containers run `docker.io/library/node:22-bookworm-slim` with `tests/fixtures/m1-s4/{http-client,echo-server}.mjs` mounted read-only. Clients send requests with `node:http`, so any header can be set. The echo upstream returns the method, URL, raw headers and peer, and sends `Set-Cookie` plus `Cache-Control: public, max-age=3600`.
- **Labels and cleanup.** Every container, network and the test image carry `io.github.thescriptingguy.notestead.test=contract`, plus a per-run label on containers and networks.
  - Each suite's `afterAll` writes all container logs, then removes its containers and network.
  - `globalTeardown` removes anything left from the run, plus the image.
  - `globalSetup` first removes leftovers of killed runs (safe under the one-heavy-job rule).
  - Verified at RED: `podman ps -a` and `podman network ls` show only the user's own pre-existing `byparr` container and network.

### Harness validation (before RED)
I validated the contract harness against a **throwaway reference stand-in**: `caddy:2-alpine` with a Caddyfile derived from the architect's spikes S2/S6, built in `/tmp`. It was never committed and has since been deleted. So the tests can pass, and RED fails for the missing feature rather than a broken harness.
- **Against the reference, every one of the 28 tests passed:**
  - static 8/8
  - headers 5/5
  - rate-limit 4/4 (exact `403×10, 429` sequences; the R3-neg variant `403×12`)
  - proxy 10/11 in the full run, including the 100 MiB round trip in 10.8 s under `--memory 128m`; the fixed C3 (below) then passed on its own
- **Sensitivity checks:**
  - With the access-log filter removed, `ac10-c8` failed.
  - With `Cache-Control: no-transform` applied before `encode`, `ac12-s6` failed (the pitfall above).
- **Two test bugs were fixed during validation:**
  - C3's delta check now uses a note item: the server lists only Joplin items in `delta`, as spike S2 also saw.
  - C3's byte-exact check uses a blob: the server re-serialises note items.

## Interpretations and findings (for the architect / orchestrator)
1. **C1-neg wording vs. ADR-0002's default.** The AC says "the same image with `JOPLIN_SERVER_HOST` unset (Host not rewritten) gets `404 Invalid origin`". ADR-0002 §Configuration says `JOPLIN_SERVER_HOST` *defaults to the host of `JOPLIN_SERVER_PUBLIC_URL`*, so unsetting it must not stop the rewrite.
   - The tests follow the ADR. The main stacks leave it **unset**, so C1 proves the default. C1-neg sets it to the web app's own host `notes.example.test`: the Host the server would see without the rewrite.
   - C1-neg therefore proves both that the Host value decides and that the override wins over the default.
   - If the architect meant "no default", the AC and ADR disagree and one of them needs an amendment.
2. **"`serviceWorker.js`" in M1-AC12** is read as upstream's actual file name, `serviceWorker.bundle.js` (spike S1 dist and F2). `ac12-s1` asserts it is present.
3. **ADR-0008 web-origin headers** (`X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`) are not in M1-AC12's text. ADR-0008 is one of this story's ADRs, so `ac12-s1` checks them on static responses.
4. **C8 covers every header of ADR-0002 rule 7**, not only the three in the AC text: `X-Api-Auth`, `Authorization`, `Cookie`, `Cf-Access-Jwt-Assertion`, `CF-Access-Client-Secret` and the `token` query parameter. It also covers both listeners.
5. **C9 checks the two Access headers that rule 3 names.** `CF-Access-Client-Id`/`-Secret` are `/mcp` credentials (M4) and are only redacted here (C8).
6. **I03 (non-empty `--out` refused)** is not an AC NEG. It follows from "nothing outside `files` exists" after import: the importer must either refuse or empty `--out`, and refusing never deletes a user's directory.
7. **Rootless podman (S6 side finding):** a request from the host through a published port reaches Caddy with a container-network source address, not 127.0.0.1. The limiter tests therefore use client containers at fixed addresses. The host-side check in `ac11-ip-default` only asserts that the spoofed values are not used.
