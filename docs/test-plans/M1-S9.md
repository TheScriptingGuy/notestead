## Command contracts (binding for the implementation)
All paths in tests are absolute. Exit codes: 0 success, 1 a finding, 2 a usage error. Every finding names what it is about on **one output line** (the tests match several needles on the same line).

### `corepack yarn check:licenses [--root <dir>] [--exceptions <file>] [--report <file>]` (M1-AC24)
- A root script (ADR-0009 A2/A7: the code lives in `packages/web-build`).
- **What it scans.** `--root` (default: the repo root). The installed tree is `<root>/node_modules` **and** the `node_modules` of every workspace declared by `<root>/package.json` `workspaces` (this repo uses `nmHoistingLimits: workspaces`, so `joplin` and its tree sit in `packages/headless/node_modules`), recursively through nested `node_modules`. A package is a directory directly under `node_modules/` or `node_modules/@scope/` that holds a `package.json`. A `package.json` deeper inside a package (for example `dist/package.json` with `{"type":"module"}`) is not a package. Symlinked workspace links may be skipped.
- **Listing.** stdout has one line per installed package with `<name>@<version>` and its declared licence text exactly as declared (for example `(MIT OR CC0-1.0)`), or a marker for none (`none`, `missing`, `no licence` or `UNKNOWN`).
- **Evaluation.** The `license` field is evaluated as an SPDX expression: `AND` binds tighter than `OR`, parentheses group; an `OR` passes if any branch passes, an `AND` only if every branch does. Allow-list (ADR-0009): MIT, ISC, BSD-2-Clause, BSD-3-Clause, Apache-2.0, MPL-2.0, the AGPL/GPL/LGPL-3.0 family, CC0-1.0, 0BSD, BlueOak-1.0.0; `-only`/`-or-later` variants of an allowed licence are allowed. A missing licence, `UNLICENSED`, `SEE LICENSE IN …`, and the legacy forms (`licenses` array, `license` object) are **never silently passed**: a legacy form may be evaluated from its `type` values or treated as missing, but a legacy `SSPL-1.0` must fail.
- **Failure.** Exit 1. One line per offending package with `<name>`, `<version>` and the offending licence (or the no-licence marker). Allowed packages are not reported as offending.
- **`--report <file>`** writes JSON: `{ "packages": [ { "name", "version", "path", "license", "status" } ] }`, one entry per installed package (duplicates of the same `name@version` at different paths are fine). `license` is the declared licence as text, or `null`. `status` is `"allowed"` (allow-list), `"exception"` (passed only by an exception entry) or `"denied"`. `path` is the POSIX path relative to `--root`.

### The reviewed exception list (M1-AC24, shared by M1-AC29)
- **Location:** `packages/web-build/license-exceptions.json` (default of `check:licenses --exceptions` and `notices --exceptions`). One file serves both mechanisms; an entry applies wherever its exact `name@version` is installed. Entries that match no installed package are not an error (recommended: report them as stale).
- **Schema:** `{ "exceptions": [ Entry, … ] }`, an optional `"//"` comment key allowed. Entry fields:
  - `name` (string), `version` (string, an **exact** semver, no range: `^0.0.1` fails)
  - `license` (non-empty string): the licence as established, or the literal `"UNKNOWN"` when none could be established
  - `evidence` (non-empty string): the licence file in the tarball, or the upstream repo URL at a tag
  - `reason` (non-empty string, not just whitespace)
  - `noticeText` (string, optional for M1-AC24, **required** when the entry stands in for a missing licence file in M1-AC29): the text the notices use
  - `prepublishBlocker` (boolean): **must be `true` when `license` is `"UNKNOWN"`** (the M5 pre-publish gate reads it)
- **Failures (exit 1, naming the entry's package):** a missing or empty `name`, `version`, `license`, `evidence` or `reason`; a version range; an entry whose package is installed only at another version (the installed `name@version` is then also named, because nothing covers it).

### `corepack yarn check:no-upstream-copy [--root <dir>] [--upstream <git-dir>] [--pin <file>]` (M1-AC25)
- Unchanged from M1-S1, plus: every **tracked** file of any size that contains upstream's licence header **together with** upstream's copyright line fails and is named; files with only one of the two, our own header, or untracked/ignored files are not named.
- **Definitions (Interpretation 4):**
  - *upstream's licence header* = line 1 of `upstream:LICENSE` at `web.commit` (the repository licence statement naming AGPL-3.0-or-later);
  - *upstream's copyright line* = a `Copyright (c) <years> <holder>` line naming the holder of the `Copyright (c) …` line of `upstream:LICENSE`, with **any** year range (an older copy carries older years).
  - Both are matched after a comment prefix (`//`, `#`, ` *`) and surrounding whitespace, in any file type.
- Deriving the two strings from `upstream:LICENSE` at the pin (through the same cached blobless tree) is recommended over hard-coding them.

### `corepack yarn check:pin [--pin <file>] [--lockfile <file>] [--headless-manifest <file>]` (M1-AC26)
- New option `--headless-manifest` (default `packages/headless/package.json`). Its `dependencies.joplin` must be exactly `cli.version` (string equality: `^3.7.1`, `~3.7.1`, `3.7.0` and a missing entry fail). The failure line names the manifest path and the field `dependencies.joplin`.
- Lockfile: for the entry resolving `joplin` and for **every** `@joplin/*` entry (lockstep and exempt forks alike), `resolution:` must be `<name>@npm:<version>`. Any other form fails; the line names the package and its protocol (`https`/`git`, `git+ssh`, `github`, `file`, `link`, `portal`, `exec`, `patch`). The check reads `resolution:`, not the key. Other packages (for example yarn's builtin `typescript@patch:…`, or `joplin-turndown-plugin-gfm`) are not checked.

### `corepack yarn workspace web-build notices <upstream-tree> --bundle <dist> --out <file> [--exceptions <file>]` (M1-AC29 seam)
- `<upstream-tree>`: an upstream checkout at `web.commit` after the recipe's `yarn install` (`yarn.lock`, `package.json`, `packages/*`, `node_modules`). `--bundle`: the built dist whose `*.LICENSE.txt` banners are read. `--out`: the file to write. `build` must use the same code path and write `<dist>/third-party-notices.txt` **before** `overlay` and `package`.
- **Coverage:** every package in the transitive `dependencies` closure of `packages/app-mobile`: workspaces contribute their `package.json` `dependencies`; npm packages their lockfile `dependencies` (optional ones included); the root `package.json` `resolutions` apply; npm aliases are listed under the real package name (`string-width-cjs` → `string-width`); `link:`/`portal:` stand-ins are not packages. Plus every package that a bundle `*.LICENSE.txt` banner names (Interpretation 6). Over-inclusion is fine. Closure packages that are not installed (platform-specific optional packages such as `fsevents`, `lightningcss-darwin-*`) cannot be in the bundle and are not required.
- **Per entry:** the declared licence and the full text of every licence file at the **root of the installed package directory** whose name starts with `LICENSE`, `LICENCE`, `COPYING` or `NOTICE`, **case-insensitively** (`license`, `LICENSE-MIT`, `LICENCE.txt`, `COPYING`, `NOTICE` all count). The copy is the installed one of exactly that version (two versions → two entries, each with its own text).
- **Upstream workspaces:** a workspace **without** its own licence file (for example `@joplin/lib`) is listed once, `License: AGPL-3.0-or-later`, with a pointer to `source.html` instead of a text. A workspace **with** its own licence file (the forks, turndown, onenote-converter, react-native-alarm-notification, react-native-saf-x) is listed like any package, with its file's text (Interpretation 3).
- **No licence file:** fails (exit 1, one line naming `<name>` and `<version>`, nothing written to `--out`) unless the exception list has the exact `name@version` with a `noticeText`; the entry then contains the `noticeText` and the `reason`.

### Notices format (`third-party-notices.txt`, parsed by `parseNotices()` in `tests/acceptance/support/licenses.mts`)
- Free preamble, then one entry per package. An entry starts with a line exactly `Package: <name>@<version>`, followed (blank lines allowed) by `License: <declared licence, or UNKNOWN>`. Everything up to the next `Package:` line is the entry body (licence texts, file names, exception reason, the `source.html` pointer). Separator lines between entries are recommended (any text that is not a `Package:` line).
- Each `name@version` appears once. No other line may start with `Package: ` and look like `x@y`.

### `overlay` and `verify` changes (M1-AC29)
- `overlay`: when `<dist>/third-party-notices.txt` exists, `source.html` links it with `href="./third-party-notices.txt"` (or without `./`), next to the existing `*.LICENSE.txt` links (which stay). The overlay does not change the file. When the file is absent, `source.html` has no such link (so M1-S2's dangling-reference check T56 stays valid).
- `verify`: fails when `third-party-notices.txt` is missing (naming `third-party-notices.txt`) or `source.html` has no `href` to it (naming `source.html`).
- `build`: `notices` (on the work tree, `--bundle` the built dist) → `overlay` → `verify` → `package`, so the file is in the tarball and in `bundle-manifest.json` `files`.

## Interpretations and findings (for the architect / orchestrator)
1. **F1: the real tree needs more than the five known dispositions (M1-AC24, T120).** A scan of this repo's installed tree (1077 packages) finds, besides the five packages the AC names, licences outside ADR-0009's allow-list: `argparse@2.0.1` (`Python-2.0`, root and headless), `caniuse-lite@1.0.30001812` (`CC-BY-4.0`, root dev tooling), `markdown-it-anchor@5.3.0` and `tweetnacl@0.14.5` (`Unlicense`), and `pako@1.0.11` (`(MIT AND Zlib)`, where `Zlib` fails the `AND`). Legacy `licenses` arrays (all MIT) appear on `exit@0.1.2`, `@joplin/fork-uslug@2.0.7`, `format@0.2.2` and `querystring@0.2.0`. T120 requires exit 0, so each needs either an exception (allowed by the AC, but `caniuse-lite` changes version often, forcing frequent re-reviews) or an ADR-0009 allow-list amendment. **Recommendation to the architect:** add `Python-2.0`, `Unlicense` and `Zlib` (all GPL-compatible) and decide on `CC-BY-4.0` (data-only) in ADR-0009; the tests don't change either way (no NEG uses these IDs).
2. **F2: 120 packages of the app-mobile closure ship no licence file (M1-AC29, T490/T90).** Measured on the S1 tree at the pin: most `expo-*`, `metro-*`, `@react-native/*` packages and others declare MIT but have no `LICENSE*`/`COPYING*`/`NOTICE*` in their npm tarball. As written, the AC makes each one fail unless it has an exact-version exception with a `noticeText`: 120 entries now, and churn on every upstream bump. **Recommendation:** amend M1-AC29 so that a package with no licence file but a **declared SPDX licence** gets the standard SPDX text for that licence plus the package's `author`/copyright, marked "no licence file in the package", and only packages with neither a file nor a declared licence need an exception. If that amendment lands, T402 is replaced by its inverse (declared MIT without a file passes with the standard text); T401 stays as it is. Until then the tests enforce the AC as written.
3. **Upstream workspaces with their own licence.** The AC says upstream's `@joplin/*` workspaces are "listed once as AGPL-3.0-or-later with a pointer to source.html". In the closure, `@joplin/fork-htmlparser2` (MIT), `fork-sax` (ISC), `fork-uslug`, `turndown`, `turndown-plugin-gfm` (MIT), `onenote-converter` (MPL-2.0-no-copyleft-exception), `react-native-alarm-notification` (MIT) and `react-native-saf-x` carry their own `LICENSE`, which under upstream's root LICENSE overrides the AGPL default for that directory. Listing them as AGPL would misstate their licence. The tests apply the AGPL+pointer rule only to workspaces **without** their own licence file and treat the others like any package (their text required). `@joplin/htmlpack` declares MIT but has no licence file; by upstream's root LICENSE it is AGPL, and the tests list it with the AGPL pointer.
4. **"Upstream's licence header" (M1-AC25).** Upstream source files carry no per-file header; the only header-like text is upstream's root `LICENSE`. The tests define the header as its line 1 and the copyright line as `Copyright (c) <years> <upstream holder>` with any years (the definitions in the contract above). A copyright line naming the upstream holder alone, or the header with our own copyright line, passes.
5. **Legacy licence forms (M1-AC24).** "Never silently passed" is tested as: a legacy array or object declaring `SSPL-1.0` fails. Whether a legacy `[{ "type": "MIT" }]` passes by evaluation or needs an exception is the engineer's choice (F1 lists the four real cases).
6. **"Named in a banner" (M1-AC29).** The banners at the pin mostly name *files* (`react-dom-client.production.js`) or describe the module ("Determine if an object is a Buffer"), not packages. The integration tests use a reviewed marker table (`bannerMarkers`: object-assign, is-buffer, buffer, react-dom, react-is, react, react-refresh, scheduler, use-sync-external-store); a marker absent at a future pin is not required, and at least one must match. `react-dom` is the discriminating case: it is outside the `dependencies` closure (a devDependency) yet bundled. The unit fixture uses the object-assign form (the package name on the first comment line). The engineer may resolve banners any way (a mapping, a file search in installed packages); over-inclusion is acceptable.
7. **Exception list in one file.** One `packages/web-build/license-exceptions.json` serves our tree (AC24) and upstream's tree (AC29). With F2 unresolved, most of its entries would be upstream ones.
8. **`ci.yml`** (ci-cd-specialist): the story goal says `ci.yml` runs these checks on both architectures. That is a workflow change outside this AC set; `check:licenses` and the `check:pin`/`check:no-upstream-copy` extensions run inside the default acceptance suite already.
