# Test strategy (living document)

Owner: `qa-specialist`. Source decisions: ADR-0007 (test strategy and harness), ADR-0005 (version pin), ADR-0009 (layout and tooling), `CLAUDE.md` testing conventions. This file grows with each story; M1-S6 added the harness, the compose test stack and the fixtures.

## 1. Standard
Every feature is proven end to end on real components, on arm64 (the Pi) and x64 (CI), by tests that would fail if the feature broke. A test that cannot fail is not a test: every acceptance criterion with a meaningful failure mode has a **negative control**, and every negative control has a **positive control** run through the same command, so a broken harness cannot pass as a "correct failure".

## 2. Pyramid
| Layer | Scope | Runner | Location | Real components |
|---|---|---|---|---|
| **Acceptance (repo-level)** | Black-box checks of the repository contract: root scripts, pin and lockfile checks, no-upstream-copy, lint rules. Runs `corepack yarn …` as a user would, against committed fixtures. | Node built-in `node:test` (see §3) | `tests/acceptance/<story>/*.test.mts` | yarn, eslint, tsc, Jest, git, the pinned upstream tree |
| **Unit** | Pure logic: MCP handlers, sanitizer, supervisor state machine, `SyncStrategy`, Data API client, config parsing, redaction, pin parsing | Jest + ts-jest; hand-written mock Data API module (`tests/mocks/dataApi.ts`, `jest.fn` per method + `resetDataApiMock()`, mapped with `moduleNameMapper`); fake timers with a pinned clock | `packages/*/src/**/*.test.ts`, `tests/unit/**/*.test.ts` | none (mocks allowed only here) |
| **Integration** | Supervisor and scripts against a real `joplin` CLI child process on a temp profile; scripts against a real upstream git tree | Jest + execa; fresh temp profile per test | `tests/integration/**/*.test.ts` | CLI, git |
| **Contract** | Real HTTP between real components: throwaway `joplin/server:<pin>` ↔ `web` proxy ↔ `headless` ↔ MCP. Suites: `proxy`, `rest-shape`, `mcp-upstream`, `headless`. | Jest + `tests/stack` podman helper | `tests/contract/**/*.test.ts` | all containers |
| **E2E** | Real Chromium against the real `web` container with server and headless running; cross-surface flows | Playwright, 1 worker on the Pi | `tests/e2e/**/*.spec.ts` | everything |
| **Release smoke** | Published artifacts on amd64 + arm64: run, health, signatures/attestations, no upstream logos, AGPL source offer | Playwright/Jest (decided in M5) | `tests/release/**` | published images, npm package, tarball |

Mocks belong only in unit tests. Contract and E2E never mock a Joplin component.

## 3. Tooling choices
- **`node:test` for repo-level acceptance tests (decided in M1-S1).** The first story has to fail meaningfully *before* `package.json`, yarn and Jest exist, and must keep working after. `node:test` ships with Node (24 on the Pi, 22 LTS in CI), needs no install, and runs TypeScript through Node's built-in type stripping. Files use the `.mts` extension (always ESM, independent of the root `package.json` `type`) and erasable-only TypeScript syntax (no enums, no parameter properties, `import type` for types). The suite shells out to `corepack yarn …` with `spawnSync` and writes one log per command under `test-results/acceptance/`.
  - The acceptance suite is **not** part of `corepack yarn test` (it runs `yarn test` itself, so including it would recurse). Jest's `testMatch` must not collect `tests/acceptance/**`; Playwright's `testDir` is `tests/e2e`.
  - Canonical command: `node --test --test-concurrency=1 --test-reporter=spec 'tests/acceptance/<story>/*.test.mts'`. Files run one at a time (resource rule: one heavy job at a time).
- **Opt-in suites (decided in M1-S2).** Tests that are too heavy for every run (the 43-minute native web build) or that need a local, uncommitted input (a real built bundle) live in `tests/acceptance/<story>/optin/*.optin.mts`. The default glob (`*.test.mts`) never matches them, so they are separate suites run by name, not skipped tests. A heavy suite that must not start by accident on the Pi fails with instructions unless an explicit env interlock is set (for example `NOTESTEAD_ALLOW_ARM64_WEB_BUILD=1`); CI runs it on x64.
- **Setup in `before` hooks** goes through `attempt()`/`settled()` (`tests/acceptance/support/webBundle.mts`): a throwing hook would *cancel* the tests in node:test instead of failing each one with the reason.
- **Static pipeline checks (decided in M1-S3, hardened in M1-S8).** Workflows are tested like code: `corepack yarn check:workflows` runs one pinned actionlint (with shellcheck pinned or disabled, so a tool on `PATH` cannot change the result) plus the repo's own rules (`[sha-pin]`, `[permissions]`, and since M1-S8 `[forbidden-trigger]` (replacing `[pull-request-target]`), `[workflow-shape]`, `[local-action]`, and `[yaml-alias]` if aliases are rejected rather than resolved). Its acceptance tests use committed `*.yml.fixture` workflows outside `.github/` (so no bot or scanner treats them as live), copied into a temp `.github/` tree per test, each a declared edit of one valid fixture; a case may add files to the tree (a local action outside `.github/actions/`) and may list alternative expectations where the AC lets the engineer choose.
- **Workflow structure tests (from M1-S8).** Requirements on a workflow's shape (which commands run on which runner, which env they get, what is uploaded under which condition) are checked by reading the workflow with the `yaml` parser in an acceptance test (`tests/acceptance/m1-s8/ac22-e2e-workflow.test.mts`), independently of `check:workflows`. Coverage is computed, not listed: every committed spec and contract test file must be matched by the commands' path filters on each runner. Such tests are validated against a throwaway reference workflow and a set of mutations before RED (never committed).
- **In-process unit tests of pipeline scripts (from M1-S8).** `.github/scripts/*.ts` use `import.meta`, which ts-jest (CommonJS) cannot compile, so their unit tests are node:test files under `tests/acceptance/<story>/` that import the module directly through Node's type stripping (`ac33-pinned-tools.test.mts`). The expected seams are declared as an interface in the test and the module is cast to it, so a missing seam fails each test rather than the type check. Time is controlled by injecting the deadline signal (no mock clock reaches `AbortSignal.timeout`).
- **Shell scripts (from M1-S8).** Every tracked shell script outside `docs/` passes the pinned shellcheck of `check:workflows` at its default severity, and every `disable=` directive carries a reason (`tests/acceptance/m1-s8/shellcheck.test.mts`, run by `ci.yml`'s acceptance step on both architectures).
- **Jest** (unit, integration, contract), as upstream. **Playwright** (E2E), as upstream, Chromium only.
- **Contract runner (decided in M1-S4).** `jest.contract.config.js` (one worker, 5-minute test timeout) collects `tests/contract/**/*.test.ts`; `corepack yarn test` never does. Its `globalSetup` builds the image under test once along the production path, calling the ESM acceptance helpers as a Node script (`tests/acceptance/support/webImage.mts`; Jest cannot load them). A setup failure is recorded, not thrown, so every test fails with the reason. `globalTeardown` removes everything the run labelled. Podman helpers live in `tests/contract/support/`; fixture programs that run inside containers (echo upstream, HTTP client) live in `tests/fixtures/<story>/*.mjs` and run on the official Node image, never on the image under test.
- **Validating a contract harness before RED (from M1-S4).** When the feature is a container, QA may run the new suite once against a throwaway reference stand-in built in `/tmp` from the architect's spike configs. It is never committed and is deleted afterwards. The run proves the tests can pass, and a sensitivity check (the stand-in with the rule under test removed) proves they can fail. The test plan records both.
- **Images built by a suite (decided in M1-S5).** Images other than M1-S4's `web` image are built lazily, once per run, by the first test file that needs them (`tests/contract/support/headless.ts`, `lazyImage`). A record per image under the run's work dir lets the other files reuse it, re-throws a build failure in every test that needs the image (RED names the missing piece), and tells `globalTeardown` what to remove. Images of this repo are built from a **clean copy of the repository's files** (`git ls-files --cached --others --exclude-standard`), as CI's checkout has them. `NOTESTEAD_HEADLESS_IMAGE=<ref>` substitutes a prebuilt image (pipeline-built, or QA's harness validation).
- **Watching a container's processes (decided in M1-S5).** Secret-leak checks sample `/proc` inside the container (`tests/fixtures/m1-s5/in-container/proc-watch.mjs`, run with `podman exec -i`), with the needles on stdin and hits reported by label only. To see the first process, the image's own command is started behind a **start gate**: `--entrypoint /bin/sh … -c 'while [ ! -e <file> ]; do sleep 0.05; done; exec "$@"' nst-gate <ENTRYPOINT> <CMD>`; the watcher creates the file after its first sample and `exec` restores the image's process tree. Every such check has a positive control: markers planted in a process's argv and environment must be found by the same run, and a `/proc` file no sample could read fails the test.
- **Absence over a window.** "X never happens" is asserted by polling over a bounded window anchored to an observed event (for example: the end of the first CLI `sync` attempt plus 60 s, ≥ 4× what the next steps take on the Pi), failing at the first occurrence. The window and its reason are written in the test plan, and a sensitivity run proves the window would catch the bug; it is the only kind of fixed duration allowed.
- **Chromium for Playwright (decided in M1-S6).** CI uses the browser of the pinned Playwright. Locally, `tests/e2e/support/chromium.ts` uses Playwright's own revision if installed, else the newest installed `chromium-<rev>` as `executablePath` (spike S4), or `NOTESTEAD_CHROMIUM`. The harness never downloads a browser.
- **Upstream test helpers** (`@joplin/lib/testing/test-utils`) are not used until proven to work outside the monorepo (they hard-code monorepo paths, findings §5). Upstream test code is reused as a *pattern* only, never copied.

## 4. Fixtures and isolation
- **Committed data fixtures** live under `tests/fixtures/<story>/`. File names encode the expectation where possible (for example `pin/invalid/<field>--<case>.json`: the checker must name `<field>`), so engineers can reuse them in their own unit tests.
- **Upstream content is never committed as a fixture.** Tests that need a verbatim upstream file generate it at test time from the pinned commit (`JOPLIN_UPSTREAM_DIR`, then `~/joplin-web-app-work/upstream-joplin`, then a raw fetch of `web.repo` at `web.commit`) into a temp dir that is deleted in teardown.
- **Upstream-derived fixtures** (from M1-S2) come from `tests/acceptance/support/upstream.mts`: `JOPLIN_UPSTREAM_DIR`, then the local reference clone if it contains `web.commit`, then a blobless depth-1 fetch of `web.repo` at `web.commit` cached in `test-results/.cache/upstream/` (blobs fetched lazily). Hash lists such as the upstream icon hashes (M1-AC7) are derived from the pinned commit at test time, never committed, so a pin bump updates them automatically.
- **Synthetic file trees** (for example a fixture web `dist/`) are generated by code into a temp dir instead of being committed when the committed form would be ignored (`.gitignore` ignores `dist/`) or linted (browser JavaScript). Each one has a self-check that it contains no upstream bytes.
- **Installed dependency trees and upstream checkouts (from M1-S9)** are synthetic and generated by code (`tests/acceptance/support/licenses.mts`): `node_modules/` is gitignored, so a committed tree would not be tracked. Checks that read real trees (this repo's `node_modules`, the S1 upstream install, T90's work dir) are compared against the tests' own reference walkers and parsers (installed packages, Berry `yarn.lock` closure, notices format), never against production code.
- **Fixtures that must be seen by a tool** (for example lint negatives) are committed with a `.fixture` suffix so no tool picks them up, copied into place for one run, and removed in `after`; the test asserts `git status` is unchanged afterwards.
- **Compose test stack and Playwright harness (from M1-S6, docs/test-plans/M1-S6.md):**
  - `tests/stack/compose.yaml` (`server`, `web`) and `compose.headless.yaml` (`headless`, one compose project per account, `init: true`, on the stack's `internal` `back` network). Every service has a compose healthcheck (string/CMD-SHELL, so override files replace it); `x-podman: {in_pod: false}` (podman-compose would otherwise put a project in one pod, sharing the network namespace).
  - `tests/stack/stack.ts` is the one lifecycle API for Playwright, the contract self-tests and the developer CLI (`node tests/stack/cli.ts up|down`). It polls container health itself (podman-compose's `up -d` neither orders startup by health nor returns for a service that stays unhealthy) and aborts naming the first `unhealthy`/exited/unchecked service.
  - **Playwright globalSetup** runs the real-server guard, then brings the whole stack (server, web, a default E2EE account and its headless service) up and healthy **before any test runs**; its teardown removes everything. Fixtures (`tests/e2e/support/fixtures.ts`): worker `stack`, `joplinServer`; test `e2eeAccount`, `headlessService` (Playwright reserves `headless`), `dataApi` (the M1-S5 probe piped to `node -` inside the headless container), `webApp` (fresh `BrowserContext` on `127.0.0.1`), automatic `stackLogs`. Since M2-S1: `plainAccount` (a fresh server user, no E2EE, no data); the option `e2eeSeed: { notes }` (default 1) for `e2eeAccount`, which seeds that many notes and records `seedTag`; and `webNetwork`, a recorder of every request of the `webApp` context (service-worker requests included) that attaches `network.log` on failure (query strings removed). **Network policy** (`tests/e2e/support/network.ts`): every request to the sync target is same-origin and under `/joplin-server/api/`; nothing goes to the server's own port; the sole cross-origin exception is `HEAD https://joplinapp.org/connection_check/`; `data:`, `blob:` and `about:` are ignored; any other request is a violation, reported as `METHOD origin+path: reason` without the query string. The recorder only observes and never routes, since routing would change upstream's behaviour (a route skips requests a service worker handles).
  - **Attachments on failure:** `server.log`, `web.log`, `supervisor-default.log` (the test's time span), `supervisor.log` (the test's own headless service), `browser-console.log`, and the `trace` of the `webApp` context. Since M1-S7 the `webApp` fixture records that trace itself (`tracing.start` without screenshots, kept on failure) and `use.trace` is off: Playwright's own trace merge stalls on Node 24 for real-app traces (docs/test-plans/M1-S7.md F2). Playwright's built-in `page` and `context` fixtures are overridden to throw and point to `webApp`, since they would record no trace (review M1-S7-r1 C-N3; `tests/integration/harness/cn3-builtin-fixtures.test.ts`). Redacted when written, then once more by the redacting reporter, which runs first and rewrites every attachment file (trace zips entry by entry) before other reporters copy them.
  - **Secret registry (from M1-S6a C1, `tests/support/secrets.ts`).** Every secret a fixture or test creates is registered: account and master passwords on `createAccount`, Data API tokens on `upHeadless` and again at teardown, and later the MCP bearer token. A test that makes its own secret calls `registerSecrets`.
    - The registry lives in process memory, plus a 0600 file (`NOTESTEAD_SECRETS_FILE`) that globalSetup creates and the redacting reporter reads and removes.
    - The worker's stdout/stderr are redacted at the source by an auto worker fixture, because `list` prints those chunks live, which in CI is the job log.
    - The reporter redacts step titles (`Fill "<value>"`), `titlePath()`, errors (message, stack, value, snippet, cause), stdout/stderr chunks and attachments in `onStepBegin`/`onStepEnd`/`onTestEnd`, and every file under the output dirs in `onEnd`.
    - Proven per channel by `tests/contract/m1-s6a/c1-pertest-secrets.test.ts`, which also covers the trace, JSON, JUnit and HTML reports and the console, with an automated negative control.
    - Pixels are never kept: screenshots, video and trace screencast frames are off (M1-S7). As a second layer, `typeLikeUser` refuses to type a known or marked secret into anything but an `<input type="password">` (C1-R1).
    - Credentials the browser obtains itself (a session id sent as `X-API-AUTH`) are learnt from each trace's network log by the reporter and redacted everywhere (M1-S7 F3); since M1-S8 (C1-R1b) also the `id` of every `…/api/sessions` response body, sent later or not. The C1-R1 leak scan collects session ids independently (`page.on('request')` and `page.on('response')`), so the scan does not share the reporter's blind spots.
    - `typeLikeUser(…, { secret: true })` registers a text no registry knows (label `typed_secret`) before the first key (M1-S8 C1-R1a).
  - **Harness self-tests** run the harness as a user does: an inner `corepack yarn playwright test -c tests/harness/playwright.selftest.config.ts selftest/<spec>` started by an outer Jest contract test. The inner run has the same reporters as `playwright.config.ts`, plus JSON. The outer test checks the exit code, the output, the JSON, JUnit and HTML reports, the files written, and the podman state before and after. Leak scans skip a file under `html/trace/` only while it is byte-identical to the file of the same name in playwright-core's packaged trace viewer (`isPackagedViewerFile`, shared with the upload gate; review M1-S6a-r1 C1-R4); a changed or unknown file there is scanned.
  - **Contract start-up sweep (from M1-S6a C4).** Descriptors record `ownerPid`, and `cli.ts up` marks its stack `persistent`. The contract run's start-up sweep removes `contract` leftovers, and `stack` resources only when no live descriptor claims them, so a developer's running stack survives a contract run. Since M1-S8 (C4-R3) `newStack()` saves the descriptor before any `compose up`, so a stack that is still starting is never swept.
  - **Descriptors at rest (from M1-S8 C5).** A descriptor holds the stack's throwaway passwords. It lives in `tmpdir()/notestead-stacks-<uid>` (`NOTESTEAD_STACKS_DIR` overrides it, for tests only), created 0700; the directory is refused if it is a symlink, someone else's, or open to group or others, and a descriptor file is read (reuse mode, `cli.ts down`, the sweep) only if it is ours and 0600-style. Stacks started before M1-S8 keep their descriptor in the old `/tmp/notestead-stacks/`, which nothing reads any more.
  - **Planted values (from M1-S8 C5).** Self-tests write the values they plant to `$NST_SELFTEST_PLANTED`, a 0600 file in a fresh temp dir outside `test-results/`, which the outer test reads and removes. Nothing named `planted.json` belongs under `test-results/`; the upload gate removes any it finds.
  - **Redaction markers and the upload gate (from M1-S8 C1-R2).** The worker writes traces unredacted and the runner's reporter redacts them afterwards, so a run killed in between (a CI timeout or cancellation) would leave them. The redacting reporter therefore writes `redaction-pending.json` in onBegin (next to each output dir, listing the output dirs and the HTML/JUnit/JSON/blob report paths) and `redaction-complete.json` in onExit, after every reporter's onEnd. CI uploads `test-results/` and `playwright-report/` only after `node tests/harness/upload-gate.ts` (`if: always()`) succeeded: it removes everything an incomplete run's marker lists, every `planted.json` and raw `.playwright-artifacts-*` dir, redacts every remaining non-hidden file with the leftover secret registries and the header/`token=` patterns, removes those registries, and writes a value-free `upload-gate.json`. Proven on a real Playwright run killed with SIGKILL (`tests/integration/harness/c1r2-killed-run.test.ts`, with the unredacted trace as NEG control). Uploads never set `include-hidden-files`, since the gate does not redact hidden files. The gate rewrites a file only when redaction changed a value (not when JSON was merely re-serialised), lists the rewritten paths in its summary, and leaves a report's `trace/` files alone only while they are byte-identical to playwright-core's packaged trace viewer (M1-S8 F1, F2). Redaction is idempotent: an already redacted value is never rewritten (F3, F4), so in a green run the gate should rewrite nothing.
  - Shared harness code (`tests/support/`, `tests/stack/`) runs under Jest (CommonJS), Playwright (ESM) and plain Node: no `__dirname`, no `import.meta`; the repository root is found from the working directory (`tests/support/repoRoot.ts`).
- **Serial rule (ADR-0007 A3, from M2-S1).** A spec that stops, restarts or reconfigures a shared service is named `*.serial.spec.ts`. It runs in the `chromium-serial` project (one worker, after `chromium` has finished). A failing `chromium` test then leaves the serial specs not run, which is accepted, since the run is already red. To run one serial spec alone, use `--project chromium-serial --no-deps`. `M2-S1-SER-04` flags disruptive calls on shared handles in any other spec.
- **Contract stacks (from M1-S4):**
  - One podman network per suite, with a free fixed `/24` chosen at run time (`10.89.200–254.0/24`) and fixed container addresses, so a trusted peer (the cloudflared stand-in) and distinct LAN clients have known source IPs.
  - Unique container names (`nst-<suite>-<role>-<run>`). Published ports are `127.0.0.1::<port>`, read back with `podman port`.
  - Readiness is a polled condition (`waitFor`, which fails fast with the log tail if the container exited).
  - Every container's log is written, redacted, to `test-results/contract/<story>/<suite>/` at teardown.
  - Labels `io.github.thescriptingguy.notestead.test=contract` plus a run id. Data-level checks read the real server directly (its published port with the `APP_BASE_URL` Host) or an echo upstream that returns the exact request it received.
- **Contract stacks with the ADR-0006 topology (from M1-S5):** a `front` network (server, `web`, the other device) and an `--internal` `back` network (`web`'s internal listener and `headless` only). Containers that must be reached by name get a network alias (`web`, `headless`); negative network checks also use the address, and a positive control by the same name proves resolution works. Per test: a fresh server user (admin API, strong unique password), a fresh E2EE "other device" (`tests/fixtures/m1-s5/device`, `joplin batch` with `e2ee enable` + `sync`), fresh secret files mounted read-only at `/run/secrets/*`, a fresh headless container and named volume. Volumes carry the run labels too.
- **Real-server guard (M1-AC19, `tests/stack/guard.ts`):** the harness refuses any `JOPLIN_SERVER_URL` that is not the published port of a running server container it started (stack labels), before it makes a single request; such a URL attaches the run to that stack (reuse mode). Automated tests never touch the user's server or notes.

## 5. Rules
- Assert on **data** (Data API / MCP / files / exit codes) in addition to the UI.
- **No fixed sleeps.** Use `expect.poll` / `waitFor` (`tests/support/poll.ts`, the one polling primitive) / readiness probes. ESLint bans `page.waitForTimeout`, global `setTimeout` calls and `timers/promises` `setTimeout` in test files, `.only`, `.skip`, `test.fixme` (ADR-0009); M1-AC1 and M1-S6 F1 prove the rules fire. M1-S6a C2 extends the ban to `setTimeout`/`setInterval` used as a value: `promisify(setTimeout)`, aliases, destructuring, `globalThis['setTimeout']`, `setInterval` delays and `timers/promises` `setInterval` (`tests/acceptance/m1-s6a/c2-lint-sleep-values.test.mts`). The rule landed with M1-S6a R1 (`e1910f8`). It also reports a string-keyed computed access to a timer on any object (write `opts.setTimeout`, not `opts['setTimeout']`), a default import of the timers modules, and global access through a type assertion (`(globalThis as T).setTimeout`). M1-S8 (FU-S6a-1, `tests/acceptance/m1-s8/fu-s6a-1-lint-sleep-modules.test.mts`) extends it to `require()`/`import()` of a timers module followed by member access, `scheduler` from `timers/promises` (`scheduler.wait`) and `Atomics.wait`. Indirect reads (`Reflect.get`, a key held in a variable, an alias of the global object, nested type assertions), `Atomics.waitAsync` and a shell `sleep` are an accepted risk (A1), with code review as the backstop. A unit test of code that schedules timers spies on the global and asserts on the spy variable (`const spy = jest.spyOn(globalThis, 'setTimeout'); expect(spy).toHaveBeenCalledTimes(1)`), never `expect(setTimeout)`, which the ban reports. Exempt: `tests/support/poll.ts` and the in-container sampler programs `tests/fixtures/**/*.mjs`. Socket deadlines (`req.setTimeout`), `AbortSignal.timeout` and Jest fake timers are not sleeps.
- **No `.only`, no skipped tests, no weakened assertions.** A failing test is fixed or the feature is fixed.
- **"Type like a user"** input helpers in E2E (real key events, no synthetic change events): `tests/e2e/support/typeLikeUser.ts`. Page objects type only through it, never with `fill`; it checks that the app accepted every character, resumes a non-secret field that lost focus, and types secrets only into password fields.
- **Per-test evidence comes from per-test sources:** the context's network log, the test's own account on the server, its own headless service. Never a shared container's log, which other workers write to in CI (M2-S1 F3).
- **Isolation:** no state shared between tests in a file; fresh context, profile and temp dirs per test.
- **Logs on failure:** server logs, supervisor logs (redacted), browser console, Playwright trace, Caddy access log (redacted). Acceptance tests write every command's output to `test-results/acceptance/**`. No unredacted `token=` or `X-API-AUTH`, and no registered secret, in any artifact, report or console output.
- **Version-pinned app under test:** every test reads versions from `upstream/joplin-version.json`; nothing hard-codes an upstream version except fixtures that deliberately test the pin checker.

## 6. Flake policy
- No retries locally. CI uses `retries: 1` with a flaky report; a test that is flaky twice in a week becomes a bug with a root cause, not a retry bump.
- A flaky test is never skipped to get green.

## 7. Where tests run (CI matrix)
| Where | Layers | Notes |
|---|---|---|
| Pi (arm64, local) | all | one heavy job at a time; Playwright `workers: 1`; installed Chromium in `~/.cache/ms-playwright` (explicit `executablePath` allowed) |
| `ubuntu-24.04` (x64) | acceptance, lint, unit, integration, contract, E2E | web bundle built once on x64 and shared as an artifact; also runs the opt-in full build suite (`tests/acceptance/m1-s2/optin/ac5-build.optin.mts`, M1-AC5, and since M1-S9 the M1-AC29 notices coverage on the build's own upstream install) |
| `ubuntu-24.04-arm` (arm64) | same | consumes the x64-built bundle |

Since M1-S8, `e2e.yml` runs the contract layer (every `tests/contract/**/*.test.ts`) and the Playwright E2E suite (every `tests/e2e/**/*.spec.ts`) on both runners, with `NOTESTEAD_WEB_ARTIFACT` pointing at the x64-built bundle artifact, checked with `sha256sum -c SHA256SUMS` before use. Its uploads go through the upload gate (§4). The contract run writes Jest JSON per runner (`--json --outputFile=test-results/…`); a Jest JUnit reporter is not required. Contract requirements: `docs/test-plans/M1-S8.md` §e2e.yml contract (static tests `M1-S8-E01`…`E10`).

**Podman versions differ between the Pi and the runners.** The Pi has podman 5.4.2; the Ubuntu 24.04 runners have the distro's podman 4.9.3, built against psgo 1.7.1. Harness code uses only podman features both have. For example, `podman top` takes only descriptors psgo 1.7.1 knows (`pid`, `user`, `huser`, …, not `uid`); an unknown descriptor makes podman 4.9 fall back to the host's `ps(1)`, which exits 125 (CI run 38874722165, `ac12-s7`). A probe whose podman command fails reports that as a harness error naming the command, not as an assertion on the product.

Artifacts on failure: `test-results/**`, `playwright-report/**`, traces, container logs. Report formats for CI (decided in M1-S6): Playwright JUnit `test-results/e2e/junit.xml` plus HTML `playwright-report/`; Jest's built-in JSON (`--json --outputFile=test-results/<layer>/jest-results.json`); node:test JUnit (`--test-reporter=junit`) for the acceptance suite.

**CI evidence (from M1-S3).** CI uploads `test-results/**` (JUnit plus the redacted per-command logs) on every run, not only on failure, and writes the per-suite totals to the job summary. A CI result counts in a test plan only with the run URL, the head SHA and the runner image; downloaded evidence is kept under `test-results/ci/<run-id>/`. An acceptance criterion that can only run in CI stays **PENDING-CI** until that evidence exists; it never gets a local stand-in test. **JUnit counts never stand alone:** node:test writes no JUnit entry for a failing `describe`-level hook, so a result is read together with the test step's exit code or outcome (shown in the job summary). Reporter options go before the file glob; node:test ignores them after it. The procedure is in `docs/test-plans/M1-S3.md`.

## 8. Ownership and process
- QA writes `docs/test-plans/<story>.md` and failing tests first (RED), then verifies and appends `## Results`.
- Engineers never edit `tests/**`; disagreements go to `## Disputes` in the test plan and QA decides in writing.
- When a test needs a production seam (a flag, an env var, an injectable clock), the test plan describes it and the engineer implements it.
- **Leftover stacks (review M2-S1-r1 P1).** A running stack or container you did not start, test-labelled or not, is reported to the orchestrator (compose project, age, labels) before anything removes it; it is removed only after the answer.
